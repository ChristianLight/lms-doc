# Assessments, marking and academic records

This scope covers ungraded practice, surveys, marked coursework, quizzes, formal exams, team assignments, feedback, moderation and academic reporting. An **item** is a reusable prompt with one or more interactions. An **interaction** is a response surface such as a choice list, text field or equation entry. A **criterion** is a rule for judging one or more responses. An **assessment** assembles and schedules items or submission tasks. An **attempt** is one sitting or submission cycle. **Marking** produces scores and feedback on evidence. The **gradebook** applies course policy to that evidence and publishes official grades. A **report card** captures academic results for a defined reporting period.

| `GradeEvidence` | Enrollment, grade item, source kind and ID, source revision, points and maximum, outcome, effective time and verification status | Accept typed evidence from approved native, manual or external sources. | `GradeResultRevision` and `GradeRelease` | Enrollment and grade item/category/offering scope, source mark revisions, policy revision, computed and effective values, status, visibility and release actor/time | Separate numerical grade, workflow state, visibility, and source. One assessment revision contains many slots. One delivery creates many attempts. One attempt contains many resolved attempt items, each of which can have several interactions and response revisions. `Enrollment` gives a learner offering-scoped access. A team attempt freezes the eligible member set and authorship for audit. The approved team mark projects to a grade result per eligible enrollment, with individually authorized adjustments where policy allows. Use stable, globally unique IDs for externally referenced records and unique scoped keys for slots and interactions. Preserve external namespace and source keys on import, including original question, variant and activity identifiers where present.

For an assessment delivery, the content placement belongs to an authorized release of the offering. A new attempt resolves the delivery against the learner’s effective course version. Within an attempt, enforce uniqueness on `(slot, occurrence)` and separately on presentation order. Within an attempt item, enforce uniqueness on `(interaction_key, revision)` for response history. Use one `AttemptSubmission` per attempt. The manifest holds response revision IDs and private immutable asset references, allowing evidence to survive the loss of an autosave projection. Use a grade result key of `(enrollment, scope_level, scope_id, revision)`. Verify that the enrollment and every grading scope belong to the same offering. Reject attempts to bind a result to a grade item outside that scope.

## Authoring and publication

1. Create or reuse items and rubrics in a scoped bank. Authors assemble fixed sections, shared stimuli and random pools. Each interaction can supply evidence to multiple criteria, and a criterion can use several responses. Version the relation that binds each criterion to an input and controls partial credit, carry-forward and feedback.
2. Provide a structured editor for rich prompts, media and accessible math. Allow learner and marker preview, worked solutions, random variant generation, alternative accepted answers and correct, incorrect, malformed and boundary fixtures. Preview as a sample learner with timing and release settings. Preview attempts use synthetic evidence and never reach the gradebook.
3. Validate required choices, point bounds, total weights, bank permissions, pool coverage, rubric completeness, schema references, translation parity, media access and accessibility. For generated variants, exercise deterministic fixtures and sample valid and degenerate cases. A fixed form, reusable pool or constrained generator must yield a comparable score scale across candidates.
4. Require an authorized reviewer to release a revision. Copy-on-write protects active deliveries. An offering may change the pinned revision for future attempts through a recorded publication decision. In-progress attempts continue on the captured form and their policy snapshot, except an audited override for an explicit action such as extending a deadline.
5. Agents use the same draft, validate, preview and review interfaces as other authors. Record the service actor and source provenance. Grant bank- and offering-scoped draft permissions, with independent publication approval. Agent-authored answer keys and tests go through the same controls.

| Interaction family | Initial assessment scope | Additional behavior |
| --- | --- | --- |
| Single and multiple selection | Stable choice IDs, answer sets, partial credit and controlled shuffling | Optional negative marking has explicit floor, cap and disclosure rules. |
| Short text and fill-in blanks | Explicit accepted answers and configured normalization for case, Unicode and whitespace | Translation and language settings govern accent sensitivity. Advanced regex uses a bounded safe engine. |
| Matching, ordering and categorization | Typed pairs, ordered sequences and per-part scores | Provide keyboard alternatives to dragging and machine-readable ordering. |
| Numerical, units and formulas | Typed numeric input, exact or tolerant comparison, approved units and elementary symbolic input as fixtures justify | Expand to equations, intervals, matrices, significant figures, generated variables and validated multi-step working under versioned evaluator profiles. |
| Long text, file and media submissions | Private evidence, rubric marking, accessible feedback, staged upload and receipt | Support team contributions, annotation and separate moderator review. |
| Composite and repeated interactions | One prompt can use multiple fields with independent or combined criteria | Advanced drawing, graphs, simulations and code use separately reviewed capabilities and are import-gated. |
| Ungraded survey and reflection | Form responses, completion rules, private or de-identified reporting policy | A truly anonymous survey stores no learner-response link. Separate eligibility and completion mechanism from anonymous evidence where needed. |

## Mathematics and evaluator safety

Authors choose what correctness means. Exact numeric comparison, error tolerance, dimensional correctness, numerical equivalence, algebraic equivalence, equality on a domain, equation solution completeness and required answer form are different rules. The same equation editor can supply a value to any of these rules. Offer typed input with a clear rendered preview and a keyboard-accessible linear path. Preserve exact rational and decimal values when meaningful. A decimal point, thousands separator or trailing zero may be part of the answer. Ambiguous locale inputs must produce a validation response. A formatting or syntax issue can be correctable during practice without consuming a try when policy allows.

| Rule | Required behavior |
| --- | --- |
| Numerical tolerance | Define `abs(actual - expected) <= max(abs_tol, rel_tol × abs(expected))` for the profile that combines tolerances. Record the comparison, tolerances and inclusivity. Use an explicit absolute tolerance near zero and reject non-finite values unless a rule handles them. |
| Units and precision | Parse into an approved quantity and unit model, check dimensional compatibility, then convert and compare. Handle affine conversions explicitly. Use original input for significant figures or required notation. |
| Symbolic equivalence | Parse a bounded grammar with an allowlist of symbols and functions. Apply approved simplification with the stated domain, assumptions and singularity checks. Persist assumptions and the actual check performed. |
| Sampling-based comparison | Use deterministic, recorded points over the defined domain and guard against singular or invalid samples. Mark with this rule only where the author approves a numerical equivalence criterion. Return an indeterminate outcome when valid evidence is insufficient. |
| Equations and solution sets | Evaluate whether each submitted solution is valid and whether the solution set is complete for the declared domain. Define order, duplicates, multiplicities and interval endpoints explicitly. |
| Required form and intermediate steps | Combine mathematical equality with separate structural tests for form such as factored or simplified. Give criterion-level credit for intermediate reasoning and define whether downstream work can earn credit after an earlier mistake. |
| Parameterized items | Version the generator, constraints and ranges. Persist chosen parameters, expected answers or their protected immutable derivation reference, order and generator version. Reject variants with undefined expressions, multiple unintended answers or inequivalent difficulty outside the declared rules. |

For example, `(x²−1)/(x−1)` and `x+1` agree where `x ≠ 1`. An equality rule must decide which domain is being assessed. A factored-form question can award equality credit to an equivalent expanded polynomial and reserve form credit for a factored response. A proof or open derivation enters manual review unless its criteria have an explicitly approved formal evaluator.

The evaluator accepts a bounded typed payload containing the item and rule references, resolved parameters, authorized response values, evaluation profile and pinned versions. It returns one of `scored`, `invalid_response`, `manual_review`, `retryable_error` or `terminal_error`, plus criterion marks, machine-readable diagnostic codes, approved learner-facing feedback, and private reproducibility evidence. `invalid_response` and service errors have their own state and policy. A failed computation never silently becomes a zero. Validate output and points against the pinned scoring bounds before persisting.

Treat all input as data. Parse through the approved grammar and pass typed values to registered evaluators. Reject unsupported operations before calling a computer algebra engine and cap evaluation before expansion or recursion can exhaust its worker. Imported author or learner scripts, unrestricted expression evaluation, network access and shell invocation are prohibited in the core. Reviewed specialist evaluators use an isolated worker with no application credentials or access to unrelated records, network restrictions, and time, memory, expression-depth and output limits. Separate the answer key and private feedback from renderer payloads, accessibility descriptions, URLs, telemetry and exports to unauthorized viewers. Disable external callbacks until their authentication, replay protection, status mapping and isolation are verified. An AI evaluation can assist a marker with evidence-linked suggestions under policy. Official high-stakes outcomes require deterministic supported rules or authorized human judgment.

## Sitting, submission and review

| Step | State and behavior |
| --- | --- |
| Open | Verify authenticated enrollment, prerequisites, audience, availability and attempt limits on the server. Allocate the ordinal and resolve random pools, variants, navigation, and overrides in one logical operation. Duplicate starts return the same active sitting. |
| Save | Autosave with idempotency and version checks. Warn about unsynced changes, show last confirmed save, and allow resume after reconnect within policy. Concurrent tabs must surface conflicts and must never silently replace a newer accepted answer. |
| Submit | Server time is authoritative. Seal the accepted response set and issue a receipt with attempt ID and acceptance time. Final submit is idempotent. Explicit policy determines whether unanswered interactions count as blank and whether time expiry auto-submits the last confirmed revision or expires the attempt. |
| Mark | Queue deterministic scoring or manual work by criterion. Preserve evidence during outage or retry. Track mark completeness independently of the attempt state. Keep partial automated marks available to authorized markers. |
| Review | Apply separate controls for submitted answers, per-item scores, correct answers, feedback, rubric detail and model solutions. Rules can release immediately, at an exam window close, or after staff approval. Learners can acknowledge feedback and request review under institution policy. |
| Correct | An authorized marker or moderator records a decision and reason. A resubmission creates a new linked attempt with its own receipt. An assigned draft-return workflow before final submission preserves response history within the existing attempt. A voided or excused attempt retains a reason and audit trail. |

Track attempt states `in_progress`, `submitted`, `expired`, `voided` and `abandoned` independently of evaluation states `queued`, `marking`, `awaiting_review`, `complete` and `failed`. A submitted attempt has one sealed evidence set and can have many evaluation runs. Expiry, final submit, and autosave serialize around the same attempt and response versions. Service retries, duplicate requests and late worker callbacks cannot reopen a sealed attempt or double-apply a mark. Default grade projection changes only after all required marks are accepted. Practice check and hint events may consume policy-defined tries within a sitting without creating new official attempts.

### Exam scheduling and accommodations

- Store open, due, close and release instants separately from duration. Use UTC for decision instants and retain the applicable time zone for display and calendaring. When both window and duration restrict a sitting, use the earlier effective deadline unless an approved override changes the window or close behavior. Clearly distinguish allowed late coursework from exam lockout.
- Configure attempt count, delay between attempts, break/pause policy, backtracking, section time limits, shuffle, password or supervised access where required, and the behavior for disconnection and resumed sessions. Require acknowledgement before beginning a high-stakes sitting and record the policy snapshot. Device disruption support records audited extension or reset actions.
- Apply accommodation settings for extra time, a separate access window, break rules, alternate presentation or a supervised alternative. Where the effective rule selects an alternate form, freeze its approved revision when the sitting starts and retain the common grade-scale mapping. For a defined rule field, a valid learner override takes precedence over an applicable group override and the delivery default. Reject conflicting overlapping overrides at the same priority or resolve them using an explicit reviewed policy. Expose effective settings to the learner and restrict access to supporting information.
- Provide accessible timing, keyboard controls, screen-reader-compatible expressions and alternatives to pointer-only questions. Test warnings, timing extensions, authentication recovery and preserved responses with assistive technology. Where a time limit is treated as essential, document the institutional decision and accommodation paths.
- Treat proctoring as an optional external integration with its own data and retention rules. Keep incident evidence and disciplinary decisions separate from marks. Review flags through authorized staff workflows. Maintain accessible supervised alternatives.

## Manual marking, moderation and regrading

A marking queue supports assignment by scope and subject expertise, anonymous candidate codes, due dates, marker comments, criterion evidence, feedback attachments and bulk review. Separate internal notes from learner-facing comments. Draft marks stay private. Authorized staff can release marks for a cohort, one learner, or a particular activity under the configured approval policy. A second marker can record an independent rubric before seeing the first. A moderator resolves disagreement and preserves both original scores and the reason for the decision. Peer and self evaluation have distinct identities, permissions, feedback moderation, and missing-review fallback. The grading policy specifies whether their contributions affect the official mark.

Use a regrade when an answer key, rule or rubric must change after learners submitted. Create a draft corrected rule and run a dry-run against affected sealed evidence. The preview shows the affected population, changed scores, missing inputs, unresolved cases and downstream course results. Select and approve a correction policy, including whether marks may decrease and whether previously published outcomes are eligible. Commit a new mark revision per approved case. When an original interaction no longer maps to a revised criterion, send it for manual disposition instead of evaluating it against a different question. Reconcile unfinished work and preserve manual overrides unless an approved decision supersedes them. Recompute affected results from the new revision set. After a formal result has been issued, use the institution's correction or appeal workflow and publish a new result or report-card revision. Keep the original receipt, released marks, approval and notification history. Author changes to new content alone never trigger a historical regrade.

## Gradebook policy and calculation

The gradebook receives accepted marks and authorized external or manual grade evidence. Normalize them into immutable `GradeEvidence` revisions that retain the original source and unit of measure. Its versioned policy determines official results. Compute gradebook values from evidence once per affected enrollment and policy, and materialize projections for staff and learner reads. The gradebook can reconcile those projections from durable inputs. Keep an explicit grade-item binding for any assessed activity that contributes to the gradebook. A lesson can require completion or mastery independently of contribution to academic grades.

| Policy area | Required decisions |
| --- | --- |
| Attempt selection | First, latest, highest, mean or staff-selected. Specify eligible states, treatment of rescoring, late rules and stable tie-breaking. Ungraded practice can be completion-only. |
| Missing or pending | Distinguish unattempted, missing after due time, absent, submitted pending review, technical exception, excused, withdrawn and genuine zero. Define each state's denominator behavior. An excused item is excluded. A missing item converts to zero only under an explicit rule after its policy deadline. |
| Aggregation | Support points-based totals, weighted categories and pass/fail thresholds. Specify item and category weighting, normalization, exclusion, drop-lowest limits and ties, bonus points, caps and floors. Define behavior for categories with zero eligible weight. Reject cycles or mutually recursive grade formulas. |
| Gates and thresholds | Store mandatory assessment passes, required submissions, retakes and separate minimum marks. Represent a gate failure explicitly even when the weighted result passes. Use versioned scales and ordered, unambiguous boundaries for letters, levels, competencies and credit. |
| Rounding | Use decimal arithmetic with a declared precision. Round at published boundaries according to a defined tie rule. Use unrounded values for thresholds unless the institution's approved policy uses rounded values. |
| Visible results | Distinguish running estimates, marks held for review, released marks and official course grades. Learner-facing aggregates may use only inputs allowed by the release policy and must identify incomplete calculation coverage. Avoid revealing withheld marks by subtraction. |
| Overrides and adjustments | Store a separate `GradeOverride` with scope, old/effective values, reason, actor, approval and effective interval. Compute the unadjusted value for reconciliation. Rollback or expiration creates an auditable state change. |
| Outcomes and competencies | Criterion results can provide evidence to mapped learning outcomes. Define aggregation, proficiency scale, required coverage and reporting separately from points and attendance. |

Each grade projection stores the ordered source revisions or a durable reference to them, the `GradePolicyVersion` and `ScoreScaleVersion`, computed and effective values, excluded reasons, coverage and calculation timestamp. A grade result revision has one scope level, item, category or offering. A `GradeRelease` identifies exact revision IDs and visible fields, audience, released time and responsible authority. Keep draft, approval and release distinct. Prevent a recalculation or integration replay from advancing a released grade pointer without the required approval. Guard locked reporting periods with a separate authorized correction operation.

An offering with homework at 40% and an exam at 60% can use points within its homework category. With homework marks 60/80 and 18/20, and an exam mark of 37/50, the result is `0.40 × (78/100) + 0.60 × (37/50) = 75.6%`. If the 60/80 item is excused, its points leave the numerator and denominator and the result becomes `0.40 × (18/20) + 0.60 × (37/50) = 80.4%`. A recorded zero, a mark pending review and an excused item have different academic meaning and must remain distinguishable in the stored record.

### Official records and reporting

1. Staff see offering- and section-scoped rosters with grade items, mark completeness, exceptions, review queues and policy explanations. A learner sees their own approved course breakdown and feedback. A delegated recipient sees only explicitly authorized learners and fields. Exports enforce the same authorization as the source views.
2. Registrar or delegated staff reviews a period close. Preview missing evidence, grades held by moderation, pending regrades, learner transfers, unapproved overrides, prerequisite gates and external source conflicts. The authority approves or records exceptions before issuing the official result.
3. Generate one versioned report card per learner and academic period under an institution policy. Each `ReportCardLine` cites the approved offering result revision and its displayed course or subject, scale, points or level, credit and completion status. Store revisioned teacher comments, outcomes or attendance summaries only where policy requires and authorized evidence is available. Record issuer identity, issuance date, publication status and any superseded document. Render accessible print and digital formats from the same snapshot.
4. Separate grade appeal intake, review, decision, publication and notification. Keep a `GradeAppeal` bound to the learner, the grade result revision challenged, evidence, due dates, assigned reviewer and resolution. A correction creates a new version of affected official records, links it to prior records, and informs authorized recipients. Withdrawal, transfer, reenrollment and course repetition preserve historic results. The transcript policy determines which grades and credits appear and which count toward program completion.
5. Support staff-level item analysis, per-outcome coverage, assessment reliability diagnostics and grade distributions from authorized evidence. Distinguish absent responses and scoring errors from incorrect responses. Restrict exports and apply policy-defined disclosure thresholds for small groups. Operational analytics are derived and must not alter official marks.

| Supporting entity | Essential fields and constraints |
| --- | --- |
| `TeamSnapshot` and member links | Delivery, learning group ID, captured version/time, member enrollment IDs and participation rights. Each member must belong to the delivery's offering and permitted audience when the team is frozen. |
| `ScoreScaleVersion` | Stable scale ID, immutable version, ordered bands, display labels, rules for grade-to-credit mapping and effective period. Validate boundary coverage and overlap. |
| `GradeOverride` | Target enrollment and result scope, reason, previous and override values, approval, visibility and supersession link. Enforce bounded values and authorized purpose. |
| `ReportCardLine` | Report card revision and released grade result revision, offering references, snapshot labels and credit values. Preserve the official display even if course metadata later changes. |
| `GradeAppeal` | Result revision, learner, filing time, scope, evidence, assigned reviewer, status and decision. An appeal cannot edit the result directly. |
| `ExamIncident` | Delivery and optionally attempt, recorded type, permitted evidence references, reviewer and disposition. Access is restricted independently of gradebook privileges. |

## Component contracts and acceptance checks

Assessment owns candidate evidence and mark revisions. Gradebook owns policy application, official results and release. Record services own report cards and transcript corrections. Keep these boundaries even when they share storage. Publish changes after durable commit, using transactional delivery or an equivalent reliable handoff. Events include an event ID, scoped record IDs, source revision, occurrence time and schema version. Example events are `AttemptSubmitted`, `ItemMarkAccepted`, `GradeResultCalculated`, `GradeReleased` and `ReportCardIssued`. Consumers deduplicate by event ID and use monotonic revision checks, with reconciliation for missed or out-of-order delivery. Events and ordinary logs omit answers, keys and sensitive accommodation details. Authorize details at the data-owning service. External package or tool grade signals enter through a scoped external grade source with explicit status, points and maxima mapping, replay handling and audit.

Index attempt histories by delivery and candidate, review queues by offering, assignment state and due time, and grade results by offering, enrollment, grade scope and revision. Use an outbox or equivalent to reconcile submission, marking and gradebook updates. A failed grading worker leaves a submitted attempt and pending work. Bulk regrades, releases and reports run as tracked background jobs with bounded batches, per-record disposition and a recovery path. Preserve submissions, grade evidence and authorized access logs according to institutional retention rules. Prefer scoped signed access to protected attachments. Record administrative actions and audit access to answer keys and academic records. Restrict publication, marking, moderation, records issuance and overrides as separate capabilities.

Acceptance checks cover the following outcomes before an assessment type or official workflow is enabled.

- A reused item changes for future offerings without changing a historical exam form, submission, mark or report card.
- Choice shuffling, randomized values, translations and seeded variants preserve response identity and can be reproduced for a dispute.
- A network interruption at the deadline preserves the last confirmed response. Retried final submission returns the original receipt. A late autosave or worker retry cannot change sealed evidence.
- Equivalent unit conversions and fraction forms score correctly. Domain holes, invalid expressions, significant figures, incomplete solution sets and form-specific marks produce the documented result. Resource exhaustion creates an actionable evaluation state without entering a zero.
- A marker can assess assigned learners and cannot access another section or hidden identities. A moderator can select a mark, and a learner cannot see it before its configured release.
- A changed key can be dry-run and corrected with no loss of previous responses, releases, manual overrides or reporting history. Retrying the correction produces one logical revision per affected record.
- Missing, excused, pending, true zero, dropped grades, retakes and category redistribution match policy fixtures. Learner views cannot infer a held exam mark from released totals.
- A late accommodation, applicable group window and learner-specific override yield the documented deadline. Keyboard and assistive technology users can complete the same assessment or its authorized equivalent.
- A term close produces a report card linked to exact released revisions. A correction generates a new issued document while preserving the original and its access history.

## Exchange and accessibility references

Use QTI as an assessment exchange contract where a published profile supports the item type and scoring rule. Define supported import/export capability by QTI version and profile, then validate using representative packages and author-scored fixtures. Treat portable custom interactions and unsupported processing as explicit capabilities requiring review. Keep native marking richer than the exchange profile where needed and report any semantic differences in a round trip. Use OneRoster gradebook services only where an external exchange contract calls for them. These contracts preserve agreed data between systems. The internal policy, evidence history and official issuance rules remain separate.
