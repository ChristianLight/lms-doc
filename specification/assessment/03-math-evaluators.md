# 03. Mathematics and deterministic evaluators

Mathematical correctness, method, precision, units, answer form and feedback are independently versioned criteria. Each published rule selects a registered evaluator build and a fixed grammar profile. It captures every assumption needed to reproduce the outcome. One learner input may earn credit for an equality criterion and lose credit for the prescribed form.

## Safe syntax and typed values

Use a versioned lexer and parser. The baseline accepts decimal literals, integers, parenthesized expressions, declared variables, selected functions and operators `+ - * / ^`. An exponent binds more tightly than unary minus, and repeated exponentiation associates right. Thus `-2^2` parses as `-(2^2)`, `(-2)^2` as its explicit group, and `2^3^2` as `2^(3^2)`. Implicit multiplication is opt-in and inserted by a deterministic token rule for adjacent number and name or number and opening parenthesis. `sin x`, chained equality, arbitrary function calls, assignment, indexing, attribute access and statements are outside the baseline. Emit parse errors at exact token offsets. Normalize supported Unicode math symbols using explicit mappings such as Unicode minus to ASCII minus. Preserve original text before mapping. Language decimal separator is configured. Do not accept grouping separators in the baseline. An ambiguous `1,234` therefore parses as a decimal only in an approved comma profile, and is otherwise rejected.

The expression parser follows this grammar. A locale profile chooses decimal punctuation and the argument separator. The baseline decimal-dot profile uses comma for arguments. A decimal-comma profile uses semicolon for arguments. Syntax and arity diagnostics report zero-based Unicode scalar offsets from the original input.

```text
expression = sum
sum        = product (("+" | "-") product)*
product    = unary (("*" | "/") unary)*
unary      = ("+" | "-") unary | power
power      = primary ("^" unary)?
primary    = integer | decimal | variable | call | "(" expression ")"
call       = function "(" [expression (separator expression)*] ")"
```

The initial function registry permits one-argument `abs`, `sqrt`, `exp`, `ln`, `log`, `sin`, `cos` and `tan` under explicit rule capabilities. `ln` is natural logarithm, `log` is base 10, and trigonometry uses radians. Require positive log inputs, nonnegative real square root input and a defined tangent in the chosen numeric profile. A rational-only rule declines transcendental nodes. A recognized function with an unapproved arity emits `FUNCTION_ARITY_UNSUPPORTED` at the function start. A separator outside a list or call emits `UNEXPECTED_SEPARATOR`. Exponent literals in scientific notation are accepted only by the declared numeric profile.

The baseline AST uses integers, decimal literals, symbol, unary, binary and allowlisted function-call nodes. Specific families add vectors, matrices, finite sets, intervals or equations with disjoint shape rules. Do not pass the input string to a language evaluator or an unrestricted symbolic interpreter. Bound input at 2,048 Unicode scalars, 1,024 tokens, 512 AST nodes, depth 32, 64 decimal digits per literal, decimal exponent magnitude 308, rational numerator or denominator at 4,096 bits, matrix at 12 by 12 and list at 64 entries. Apply fixed evaluator-specific complexity limits before expensive expansion. The initial polynomial evaluator allows at most six variables, total degree 16 and 1,024 nonzero terms. A rule can tighten limits. Raising a cap creates a tested evaluator profile. Scope expressions and symbols to the item.

Keep exactly represented values as reduced rational pairs with positive denominator. A decimal literal is an exact coefficient and exponent when the rule asks for exact values. A bound on literal exponent applies before allocation. For approximate transcendental operations use one published precision, approximation implementation and deterministic error bound. NaN, infinity and undefined are distinct diagnostic states. Non-finite values require a separately approved rule. Decimal output to grading uses no exponent or grouping separators. Scores retain at most six fractional places under an explicit half-even rule at the published criterion boundary.

## Evaluator catalogue

| Evaluator | Author parameters | Deterministic operation |
| --- | --- | --- |
| Exact rational | Expected value, permitted forms, score | Parse to reduced numerator/denominator. Equal means both match. For fraction-in-lowest-terms inspect original literal numerator and denominator independently. |
| Numerical tolerance | Reference, absolute and relative tolerances, inclusive edge, precision profile | For finite compatible values, accept when absolute error is no greater than the larger of absolute tolerance and relative tolerance times absolute expected. Use the unrounded canonical quantities. |
| Unit-aware | Expected unit code, allowed units, required unit policy, comparison, permitted scale | Parse approved unit atoms, normalize dimensions and scale, then compare. Reject dimension mismatch. Affine units require a simple unit token and explicit affine family. |
| Precision and form | Required significant figures, decimal places, exact form, order convention | Inspect original tokens after notation normalization. A decimal zero can encode scale. Record whether scientific notation or unit conversion affects the stated format requirement. |
| Polynomial equality | Declared symbols, coefficient field, max degree | Convert to a sparse map keyed by monomial exponent tuples. Expand within cap, combine rational coefficients, remove zero terms and compare sorted canonical maps. |
| Rational expression equality | Polynomial bounds, domain constraints, variable assumptions | Normalize numerator and denominator. Compare cross products for value equality. Separately prove denominators nonzero on the declared domain or prove excluded sets equivalent using the supported domain profile. Unproven exclusion is indeterminate. |
| Domain-defined symbolic | Allowed operations, assumptions, proof profile | Apply registered rewrite/decision procedures preserving the declared domain. Retain a private strategy trace. Return indeterminate if rules cannot establish equivalence or a counterexample. |
| Sampling comparison | Point list or deterministic finite sampler, domains, minimum valid points and tolerances | Evaluate candidate and expected at each eligible point under pinned numeric semantics. Any valid counterexample rejects. Insufficient comparable points is indeterminate. Success is the sampled criterion. |
| Equation or solution set | Domain, exact equation, finite expected roots or certified solver, multiplicity policy | Check each submitted value satisfies the equation and is in domain. Compare coverage against all declared exact roots or a supported solver's certified result. Apply set or multiset semantics per rule. |
| Vector, matrix, interval | Shape, element comparison, dimension and endpoint policy | Compare dimensions, entries or canonical interval union. Open/closed ends remain distinct. Distinguish a scalar and a length-one vector. |
| Structural form | Expected root/operator forms and constraints such as factored or simplified | Check AST patterns independently of algebraic value. Sort commutative factors only if allowed. Reject cosmetic wrappers that do not satisfy the declared pattern. |
| Step validity | Directed sequence, allowed transformations, domain, criterion maxima | Validate each pair of consecutive supplied expressions under the stated transformation. Record form or transition-specific feedback, then apply explicit carry-forward policy. |
| Constructed proof | Rubric and adjudication rules | Default to authorized human marking. A formal proof checker may be installed as an independently approved registry capability with bounded theorem language and compatible fixtures. |

### Specific calculations

- With expected 12.00, absolute tolerance 0.05 and relative tolerance 0.01, use the larger tolerance 0.12. A response of 12.12 passes with an inclusive edge. 12.121 fails. Expected 0 with relative tolerance 0.01 and absolute tolerance 0.005 accepts 0.004 and rejects 0.006.
- Comparing 180 cm to 1.80 m uses a scale of 1/100 and yields exact equality. Comparing 36 km/h to 10 m/s uses 36 × 1000 ÷ 3600 = 10. A mass unit entered for a distance fails the dimension criterion. 25 °C maps to 298.15 K under the affine temperature rule, while a change of 25 Celsius degrees maps to a change of 25 K. Version the distinction between quantities and temperature differences.
- For a required three significant figures under the explicit decimal rule, `1.20` passes and `1.2` fails despite equal numeric values. `0.00450` has three significant figures. Without a decimal marker, a trailing zero in an integer such as `1200` is ambiguous. Require scientific or explicit decimal notation when precision is assessed.
- In the real domain, `sqrt(x^2)` equals `abs(x)`. It equals `x` under the added assumption x ≥ 0. The sample x = −2 supplies a valid counterexample to unrestricted equality with x. Square root simplification must preserve the assumptions.
- Over all real x, `(x^2-1)/(x-1)` has a domain hole at 1 and is unequal as a function to `x+1`. It passes value and domain comparison on the declared domain excluding 1. Numeric sampling must separately account for the case where exactly one side is undefined.
- For `x²=9` over the reals, `{3}` earns the correctness part but misses completeness. `{-3,3}` earns both. A duplicate pair `{3,3}` fails a declared distinct-set syntax rule before scoring. A multiset comparison is used only when multiplicity is an assessed outcome.
- For `x²+2x+1` to be factored, allocate 3 marks for algebraic value and 2 for an approved factored structure. The response `x²+2x+1` earns 3, `(x+1)^2` earns 5 and `(x+2)^2` earns zero on the dependent form criterion even if structurally factored. The dependency is published.
- In a composite calculation worth 6, give 2 for the initial quantity, 2 for the stated formula, and 2 for the follow-on result. An incorrect initial quantity of 9 instead of 10 earns 0. Correctly using the formula 3q and answering 27 earns 2 for the formula and 2 for the follow-on if and only if the pinned carry-forward rule permits grading relative to a structurally valid earlier response. An invalid or unsafe earlier value routes dependent credit to the configured review outcome.
- For interval union equivalence, `[0,1) ∪ [1,2]` merges to `[0,2]`. `[0,1) ∪ (1,2]` preserves a gap at 1 and fails equality. Sorting and merging use exact endpoints in the published numeric profile.

## Criterion orchestration

Validate that criteria form a directed acyclic graph. Evaluate in topological order with stable criterion-key ordering among ties. Each criterion declares point bounds, prerequisite success condition and missing, invalid and indeterminate dispositions. The default blank yields zero on its own criterion, dependent criteria that require a valid value are unresolved or zero by the published rule, and a transient service failure stays pending. No combination treats a service failure as a learner answer. A criterion may explicitly call for manual review on an indeterminate computation. Final item marks sum accepted criterion values and use the published score floor/cap. Persist all criterion dispositions and the algorithm digest even when the item has one criterion.

Required evaluator fixtures include boundary tolerance, equivalent formats, degenerate variants, wrong dimension, unknown variables, singular points, equal-but-wrong-form, unexpected literal precision, acceptable alternative answer and resource exhaustion. Where sampling is used, persist points and excluded points, precision, observed comparisons and reason codes. Numeric comparison where exactly one side is undefined fails the function-domain comparison if that point is in domain. If both are undefined at a point excluded by the declared domain, replace it with a deterministic eligible point. Exhausting the search budget returns indeterminate.

## Evaluator installation and operation

An EvaluatorRelease contains type key, version, request/response schema digest, worker digest, trust state, approved profiles and dependency build identities. Install requires independent approval, passing verification fixtures and isolation checks. An approved release becomes usable by newly published rules. Deprecation stops new publications. Security revocation stops execution and leaves historic results and sealed work intact. Regrade pending evidence with an approved substitute only after a dry run and compatible mapping.

Run builtin typed scorers in a resource-limited evaluation pool. A specialist worker receives only the job payload and no application or file credentials. Default per run ceilings are 250 ms CPU for elementary scoring, 2 s for approved symbolic scoring, 128 MiB memory, 64 KiB output, no network and an ephemeral read-only code environment with a bounded scratch space. A trusted service can raise thresholds for a declared profile after resource tests. Enforce tenant rate limits, bounded queues and cancellation. No authored or imported Python, PHP, JavaScript, shell code or unrestricted computer algebra input executes in the LMS core. Convert verified imports into registered rules or route them to human remediation.

A deterministic evaluator receives the evaluator digest, resolved item and rule IDs, variant profile, validated input payload, grammar and unit profile and input digest. It returns `scored`, `invalid_response`, `manual_review`, `retryable_error` or `terminal_error`. It also returns bounded criterion outcomes and a safe feedback code. Private diagnostics are separate. Require matching input digest and schema, unique known criterion keys, finite canonical score values, approved codes and observed resource use before accepting output. Retry network or worker faults with bounded backoff. Parse errors and indeterminate symbolic cases do not retry with a larger hidden budget. A replay of identical inputs under the same registered deterministic release must produce the same normalized result digest. Discrepancy opens an incident and stops automatic acceptance for that release. See [UCUM](https://ucum.org/ucum) for unit representation and [OWASP resource limits](https://api-security.owasp.org/editions/2023/en/0xa4-unrestricted-resource-consumption/) for service boundaries.
