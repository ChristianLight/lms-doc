# 04. Assessment assembly and deterministic forms

An Assessment identity has multiple AssessmentVersions. A published version pins its section structure, slot selection, scoring scale, compatible interaction and evaluator versions, variant rules and navigation profile. An AssessmentDelivery binds it to an eligible offering and placement. Each start realizes a candidate-specific form and freezes the form before serving any question.

## Sections, slots and pools

An AssessmentSectionVersion defines a stable section key, order, instructions, selection constraints, navigation mode and optional duration. An AssessmentSlot belongs to an assessment revision and section. It has slot key, order, fixed revision or ItemPoolVersion, number of occurrences, point maximum per occurrence, shuffle settings, required flags and pool constraints. Fixed slots have one occurrence by default. A pool is an immutable reviewed list of eligible ItemVersions with declared difficulty bands, locale, outcome tags, capability requirements, incompatibility groups and applicable variant profiles. An item may carry several tags. Record coverage calculation by explicit tag membership. A tag-based authoring query produces an immutable reviewed pool when published. Running a query at exam start would make the test change when the bank changes.

Default constraints select without replacement across an assessment and forbid the same stable Item in different slots even when revisions differ. An author can allow repeats only where deliberate and disclosed. Fixed items reserve their stable IDs first. A pool slot reserves enough distinct allowed items to satisfy all later constraints. If every item in a declared pool has compatible max 4 points, selecting three yields 12. A mixed pool requires per-slot score normalization `slot_max × earned / item_max`, expressed as exact rational arithmetic before item publication boundary rounding. A zero-max item is allowed only in ungraded slots. Comparability based on metadata needs human review for high-stakes exams.

Publish a navigation manifest listing sections and slot positions. A preview simulator displays several different candidate forms, sampled coverage counts, expected maxima, warnings, variants and timing. Require at least one known feasible solution with each supported locale and alternate policy profile. A blocked or withdrawn dependency can prevent new candidate starts even when the assessment remains published. Raise an operations alert and give the candidate a neutral failure reason. Never silently change a fixed item or substitute an unreviewed pool.

## Reproducible selection algorithm

1. Under the start reservation, derive an opaque 256-bit seed from an institution-managed secret and canonical bytes of delivery ID, candidate reference, attempt ID and form profile version. Store seed encrypted for authorized replay and record key version. Persist the realized form for ordinary reads and disputes. Key rotation does not change the form.
2. Build one ordered problem per unfilled slot occurrence from eligible pinned choices. Exclude fixed items and versions incompatible with approved candidate locale, registered render capabilities, accessibility alternative and dependency status. Evaluate all inclusion decisions against one eligibility snapshot.
3. Assign the constraint search order by ascending remaining candidate count, with ties broken by section order, slot order and occurrence. For each ordered position, rank eligible candidates by lexicographic unsigned bytes of `HMAC-SHA256(seed, domain || slot_key || occurrence || item_version_id)`. Encode the domain and slot key as UTF-8 with each byte length prefixed by an unsigned 32-bit big-endian integer. Encode occurrence as unsigned 32-bit big-endian and item identity as 16 raw UUID bytes. Use domain `item-pool-v1`. Break digest ties by ItemVersion UUID bytes. Perform deterministic depth-first search in that order with forward checking against remaining unique choices, remaining minimum coverage and maximum limits. Mark a branch impossible as soon as it exceeds a maximum or cannot satisfy a minimum even under optimistic remaining capacity.
4. Reserve at most 20,000 visited search nodes per form by default. A hard budget error is separate from unsatisfiable constraints. Publication requires a budgeted feasibility check using representative seeds. If runtime cannot resolve a form, preserve no candidate-visible partial sitting or spent attempt ordinal. Record the rejected allocation attempt separately and return a retryable operations-facing error only where a subsequent attempt could succeed.
5. Derive choice order by ranking each choice with separate domain `choice-order-v1` plus AttemptItem identity as 16 raw UUID bytes and the length-prefixed UTF-8 interaction key and choice key in that order. Respect fixed-position options and order-sensitive dependencies. Record resulting choice list. The option key in the response always remains the definition key.
6. Store AttemptItem with stable slot reference, occurrence, resolved ItemVersion, relative order, realized public rendering inputs, approved locale, maximum and protected evaluator inputs. Store form digest over ordered canonical records. Ensure form and policy are committed with the start receipt.

Consider two positions P1 and P2. P1 can select A or B. P2 can select only A. A greedy allocation by visual order might choose A for P1 and fail. The constraint order visits P2 first, reserves A, then gives P1 B. If each position can select only A and repetitions are forbidden, the preflight rejects the assessment profile. If A and B both count toward topic X and the form permits at most one X, publication must supply at least one eligible item outside X or relax that constraint through review.

## Item variants

A VariantProfileVersion owns parameter schema, finite generator or approved deterministic generator registry key, derivation rules, domains, forbidden values, generator limit, option permutation policy and sealed evaluator values. A generated parameter may be public in the stem and still have private derivative values. Parameterization never evaluates raw author code. Use a versioned declarative subset for bounded arithmetic, finite set selection and relational constraints. Reuse math grammar semantics for typed parameters, but keep generation and grading permissions separate.

The finite sampler chooses an unbiased index from random digest blocks. Interpret each block as an unsigned integer x with 256-bit range. For cardinality n, compute limit `2^256 - (2^256 mod n)`. Reject x at or above limit and use the next block. Otherwise choose x modulo n. Maintain separate HMAC domains for parameter, retry counter and shuffle. A named parameter may depend only on earlier typed parameters. Reject cyclic dependencies. Evaluate constraints and answer uniqueness. Persist selected parameter vector, iteration count, generator digest, public resolved values and protected expected values or immutable derivation reference. Default generation limit is 64 iterations. During author validation require exhaustive evaluation of finite combinations of size up to 10,000 and representative deterministic fixtures plus evidence of structural constraints above that limit.

Example parameter set chooses integer a in {1,2,3} and b in {0,1,2} for `ax+b=0`. A division rule excludes a = 0 structurally. If the course requires nonzero root, exclude b = 0. The vector a = 3, b = 2 yields exact root −2/3. Candidate syntax −0.667 is accepted only under a published tolerance or decimal answer rule. A corrected generator range changes future revisions. The historical form records a = 3, b = 2 and its accepted scorer.

Do not generate each answer on every reload. Shared stimulus values are resolved once per form and linked to downstream items. Inter-item answer dependency is exceptional. Declare a directed acyclic dependency and freeze all relevant public inputs. Never reveal a later stem that discloses an earlier answer under restricted navigation. Validate generated distractors do not normalize to the correct answer or to each other.

## Lifecycle and failures

Independent assembly review checks the exact draft, dependency and fixture digests and produces an AssessmentAssemblyReview. Publication stages resolved metadata and compares that approval before atomically advancing the AssessmentVersion pointer. Preview forms use separate seeds and IDs and never count as attempts. Delivery version changes affect new starts only. During an operational safety issue, a delivery suspension blocks new starts and defines whether current sessions continue or receive a separately approved suspension adjustment. Existing form bytes remain inspectable under permission. Invalid locale content, missing bank authorization, unsupported rendering or evaluator profile and infeasible form selection use separate error categories. Candidate messages indicate availability and next action without revealing exam composition. Admin diagnostics identify the exact version and validation failure.

The transfer importer maps selection and variation semantics only where it can preserve them. A candidate-facing HTML snapshot can preview visual content but cannot replace an executable grading or variant contract. Compare source and destination with fixed-form test vectors before activating deliveries.
