# 06. Attempt lifecycle, saving and immutable evidence

A sitting is one Attempt bound to AssessmentDelivery, candidate Enrollment or TeamSnapshot, sequence, assessment version, policy version and one resolved form. Use transactional writes and a uniqueness constraint covering delivery, candidate kind, stable candidate ID and ordinal. The stable ID is Enrollment for individual work and LearningGroup for team work. TeamSnapshot identifies the captured roster, while the stable LearningGroup keeps quota and active-attempt uniqueness intact across membership changes. Candidate membership, device lease and response validity are checked independently. A started attempt belongs to one offering. Individual work pins its exact EnrollmentRelease. A team pins the exact release for every member in the frozen TeamSnapshot. The captured ContentPlacement belongs to the CourseVersion of all those releases. Any new authorized sitting receives a new ordinal. A preview or failed form allocation consumes none.

## Records and access

Attempt stores UUID, lifecycle, terminal reason, candidate type and reference, start and current deadline, timestamps, maximum points, policy snapshot hash, realized form hash, draft version and lease revision. AttemptItem stores attempt, slot, occurrence, order, resolved item and variant, max points and sanitized candidate snapshot ref. ResponseRevision stores unique attempt item and interaction key and monotonic response revision, typed values and canonical hash, validation state, writer, operation id and accepted instant. AttemptSubmission has exactly one row per attempt, immutable ordered manifest, manifest digest, receipt ID, finalization actor and type, actual and effective times, blank inventory and scoring profile digest.

The owner sees their own candidate representation and allowed review only. A team editor is an authenticated member of the frozen attempt team with edit rights, and must still have eligible current access. Markers access the sealed evidence for assigned cases. A supervisor can view timing and state without answer values. Private asset leases are attempt scoped, digest checked, short-lived and revoked on permission loss. Store uploaded evidence under immutable asset versions. A new upload revision never overwrites already sealed evidence.

## Attempt transitions

| State | Transition | Guard and effects |
| --- | --- | --- |
| In progress | Start | Allocate form, reserve ordinal and create candidate lease together. Record idempotent start response. |
| In progress | Save | Check lease, effective time, navigation and response revisions. Append immutable evidence and update projection atomically. |
| In progress | Pause or resume | Applicable policy and current time allow it. Advance lease/session version and record authorized timing adjustment. |
| Submitted | Candidate finalization | Require authorized candidate and exact version, accepted deadline, blank acknowledgement if applicable, and scanned assets. Seal evidence and enqueue evaluation. |
| Submitted | Automatic finalization | Deadline reached, policy selects auto submit. Use latest valid acknowledged revisions, even if blank. |
| Expired | Expiry without auto submission | Deadline reached and policy selects expiration. Preserve drafts and terminal reason. |
| Abandoned | Abandon | Explicit candidate action when policy allows. Preserve previous evidence and consumed ordinal. |
| Voided | Approved invalidation | Create protected disposition and mark existing GradeEvidence superseded if applicable. Preserve original receipt and mark provenance. |

Marking, appeal, disclosure and academic state are orthogonal. A submitted attempt with complete marks remains submitted. Revision of a mark changes its grading history, never the submission state or accepted answers. Granting another attempt records permission and reason instead of deleting the previous attempt.

## Idempotent start

Idempotency key scope is Principal plus delivery plus action. Canonical payload includes candidate enrollment or team plus policy acknowledgement. After authorization, a retry with same canonical payload returns the original start result even if the window has closed. A different payload for a used key returns `409 IDEMPOTENCY_KEY_REUSE`. Recheck access before returning a stored representation. Serialize active attempt reservation by delivery and candidate. If a distinct request already started the candidate's attempt, return `409 ATTEMPT_ALREADY_ACTIVE`. Authorized availability supplies the current attempt pointer without a writer lease. The exact same authorized request replay may recover its original receipt. A new session follows its own approved lease or takeover flow. Allocate the visible form only after eligibility. Stage or discard form computation if transaction retries. Source seed inputs and attempt UUID remain stable across internal retries for the same reservation. Enforce uniqueness of a writable sitting per candidate and delivery.

### Course release changes

The availability response includes the effective EnrollmentRelease ID for an individual and current membership revision for a team. Start supplies the corresponding expected version. Team start identifies the stable LearningGroup and creates the TeamSnapshot in the same authoritative transaction. In the start transaction, require a Participation-owned release reservation or equivalent serializable check that both start and rollout honor. A rollout that has advanced the release before start wins returns `ENROLLMENT_RELEASE_CHANGED`, no ordinal and no consumed admission grant. Where enrollment and assessment storage share a transaction, use the same owner-coordinated enrollment lock. Teams acquire all member locks in ascending enrollment UUID order and fail atomically if any member no longer has a compatible release. The Participation owner controls its storage. The cross-domain release mechanism follows [course rollout](../curriculum/03-publication-and-rollout.md) and [availability](../participation/03-availability-and-dates.md).

With distinct stores, Participation issues a short fenced launch reservation for the exact enrollment release and durable attempt request ID. Rollout checks that reservation and active registration state before ending the release. Assessment claims the reservation once, commits the attempt with the captured fence token, then durably reports success or failure. An unknown outcome keeps rollout deferred until reconciliation queries the assessment request receipt or the assessment owner proves the reservation cannot commit. Mere expiry does not establish that a start failed. Existing timed sittings retain their pinned release if an authorized exceptional rollout happens before finalization. Current enrollment entitlement still governs subsequent session access.

## Save operation

A save is an atomic batch of edits with candidate lease ID, navigation context and an expected revision per changed interaction. Use a request idempotency key and optional global form ETag for navigation-affecting actions. Independent fields can merge because each checks its own revision. Do not use last-writer-wins for the same field. An edit to an untouched response uses expected revision 0. Validate all fields, then in one short transaction lock attempt, get authoritative admission time, verify state and current lease, compare expected revisions and append all or none. A rejected batch returns all authorized field conflicts without echoing hidden evidence. Invalid envelope rejects the entire batch. Ordinary per-response validation failures return exact interaction key and message code.

Concurrent tabs default to one candidate writer lease for a formal exam. Taking over from a second device requires reauthentication or staff approval where published and revokes the first lease. Late writes from the old lease fail even when revision numbers happen to match. In collaborative coursework, each eligible member has a distinct lease and per-field version checks. Keep append-only accepted revisions until retention permits deletion. The draft projection is a cache of heads and is rebuildable.

A retry after an acknowledged save races the deadline or lease takeover. Re-evaluate whether the caller may access the record, then replay its already committed result even if a fresh save would be rejected. Persist idempotency and domain updates together. Key entries for formal submission are retained with receipt indefinitely under academic retention. Short-lived saves keep request keys for at least the configured reconnection interval and until attempt sealing plus one day by default. Request keys never contain raw answers. A reuse conflict compares canonical payload digests.

## Finalization and deadline races

1. Validate request authorization and preconditions. Candidate finalization supplies the exact current form draft ETag, lease and explicit blank acknowledgement if configured. The unchanged draft ETag binds that acknowledgement to the displayed blank set. Candidate submits no answer bytes with finalization. Use a save, then finalize with the acknowledged revision. Staff can record an authorized timing adjustment. The ordinary candidate finalization command always requires a candidate writer lease.
2. Lock attempt, read authoritative decision time and load latest accepted response heads. If already submitted, return canonical receipt on an authorized identical retry, with no new row or event. If an unrelated terminal state won, return that state. If now at or beyond deadline, run the expiry policy once within the same lock.
3. In a candidate finalization, reject when ETag changed since blank acknowledgement or required scans remain pending. Expiry uses approved attached versions and records excluded quarantined or pending assets as absent with reason. Store candidate response IDs and blank markers in a canonical section/slot/occurrence/interaction ordering. Seal manifest digest and receipt metadata.
4. Advance attempt state and write outbox event in the same durable transaction. A subsequent worker loads the event, confirms manifest and schedules one compatible job per marked item. If the worker is unavailable, candidate still sees a receipt and marking remains pending.
5. Display authoritative receipt status and review rights. A lost HTTP response after durable commit is recovered by retry or GET. Late candidate saves cannot mutate sealed evidence. Administrative staff corrections create linked attempts or grading revisions.

With one writable attempt and responses at A=3/B=1, Device 1 saves A with expected 3. Device 2 saves B with expected 1 under an authorized collaborative lease. Both may succeed in either order. A subsequent Device 2 save of A with expected 3 fails after Device 1 created A=4. If finalization wins before the second B save, the manifest stores B=1 and the late save fails. If B=2 wins but the candidate submits the older ETag, finalization returns 412 and must be reconfirmed, unless forced expiry already sealed the newer state.

## Storage, recovery and UI

Use indexes for active attempt by delivery and candidate, due attempt by state and deadline, response head by attempt item and key, finalized evidence by attempt and digest, grading work by state and lease expiry. Record separate candidate status and operation data. Never log full request payloads. Store state changes and overrides in an audit trail. A candidate-facing activity records just saved, sealed, marked and feedback available. It does not send hidden scores. Cross-instance disaster recovery must preserve unique submission receipts, data versions and outbox sequence. Detect corruption by reconciling manifest hashes and mark input digests before restoring candidate access.

The sitting screen shows an autosave state, timer, per-item completeness and allowed navigation, bookmarks and response validation. Candidate can download or print a minimal receipt where policy allows. Accessible error recovery shows affected response key with focus restored to editor, preserving local text only under the device policy. For high-stakes exams, prohibit offline acceptance and show connection loss distinctly. No browser claim of a local timestamp can bypass the server cutoff.
