# Joomla runtime composition and format boundaries

This is the Joomla 6 and PHP deployment of the [portable native curriculum model](../persistence/01-relational-content-storage.md). Joomla owns authenticated site routing and host permissions. The LMS owners control academic scope, publication, attempt state, marks and records. Joomla Component Builder maintains the editable extension source. The compiled Joomla extensions serve native PHP learning and administration. Exchange format adapters read and write validated native contracts.

## 1. Two learner runtime paths

| Learner opens | Runtime authority | Learner output | Server evidence |
| --- | --- | --- | --- |
| Native lesson, document or media activity | Curriculum and participation owner services in Joomla PHP | Accessible native Joomla view produced from exact node and placement versions | Authorized placement access and the declared progress or completion evidence |
| Native practice, quiz, assignment or exam | Assessment owner services in Joomla PHP, with approved evaluator services and bounded background work as needed | Candidate-only form, allowed saved responses and separately authorized feedback | Pinned Attempt, exact ResponseRevision, sealed AttemptSubmission and accepted mark evidence |
| Imported SCORM package retained as a package activity | Interoperability owner authorizes the launch. Isolated browser player implements the exact edition API | Package-provided HTML, JavaScript and media inside the launch boundary | Package registration, exact runtime sequence, durable commit and policy-mapped evidence |
| Exported SCORM package launched by another LMS | The receiving system and its edition support | Portable launch resources and the behavior declared by the exported profile | Receiving system's runtime state and outcomes under its own rules |

A SCORM package is executable browser content. Joomla PHP authenticates and grants access to a hosted package, validates its server-side runtime evidence and applies native outcome policy. The Shareable Content Object calls its edition's browser API. Native lessons and assessments run directly in the Joomla course and assessment views. The native workflow needs no SCORM wrapper, vendor course runtime or source application server.

A native assessment can use JavaScript for editor interactions, mathematical presentation, timers and accessible progressive enhancement. PHP owner services validate the authoritative request, release and attempt, persist accepted responses, and apply an approved evaluator with explicit resource limits. A client timer, score field or offline form preview supplies no official authority. Nextcloud remains the authorized collaboration provider. Filery remains the selected document adapter subject to its declared capabilities. Provider unavailability does not convert a native lesson or exam into a package runtime. See [provider boundaries](04-collaboration-and-document-adapters.md).

### Forms and persisted child data

Use a normal JCB form for simple supported scalars. A compound value such as the complete option list of a choice interaction can use a structured editor that submits the validated versioned value. A normalized editor for records with independent rows needs the actual child Admin View, component attachment, fields, parent GUID and matching read/write handlers. The inspected expert model recipe uses a non-database parent field and both `on_get_model_field` and `on_save_model_field` handlers. Confirm their actual attachment and activation in the selected compiler. Generic replace-all handlers apply only where owner lifecycle and failure rules allow. For an immutable version, the form stages the new set and the owner command seals a new version. [JCB normalized subforms](https://github.com/joomengine/skills/blob/e7b8723397811772c85358e72ce91ab594785748/packages/workflows/normalized-subforms.md)

For example, the course authoring editor shows one outline tree built from DraftPlacement rows. Text and media details come from the referenced type-specific definition. Editing a node body stages a new revision. The draft command changes a placement's revision pointer after validation. Another teacher can keep using the old release, while the approved new release proceeds through enrollment rollout. The assessment editor shows ordered InteractionDefinition rows in their prompt context. The protected scoring surface edits a separately authorized rule or binding. Rendering the author preview never inserts an Attempt or a grade.

### SQL source and migration discipline

Record generated field type, null handling, length, index and table settings in JCB. For physical details that ordinary field metadata does not express, use maintained native authoring inputs, including component SQL and the `component_updates.version_update` MySQL rows and supported installer hooks. The selected release must produce the verified database contract on fresh install and upgrade. If a compiler history comparison creates a migration during one build, preserve the required migration in maintained source and verify a fresh import can reproduce it. The presence of an update file does not repair a fresh install schema. [JCB component assembly and updates](https://github.com/joomengine/skills/blob/e7b8723397811772c85358e72ce91ab594785748/packages/models/component.md) · [Joomla extension manifests](https://manual.joomla.org/docs/building-extensions/install-update/installation/manifest/#sql-schema-numbering)

The delivered package contains components and their genuine runtime extensions built from the maintained graph. All application behavior, including custom adapters and installer work, stays reproducible from that source. Inspect compiled files and ZIPs as build outputs. Return a needed change to its authoritative Field, Admin View, hook, Custom Code, Power, plugin or asset record and compile again. A direct edit to emitted PHP, XML or SQL, or an extra override package applied after compilation, is outside the implementation contract. Native compiler plugin capabilities are available for a documented build requirement that supported ordinary records cannot express. Such a plugin must be part of the reproducible authoring environment and cannot substitute for owner services or an untracked output patch. ## 3. Native PHP request flow

1. A Joomla site or administrator route resolves the current authenticated host account. The trusted account binding identifies the exact Principal in its institutional context. Apply coarse host permission and current LMS scope separately.
2. The curriculum player selects the learner's effective EnrollmentRelease and exact ContentPlacement. Authorize the placement and its dependency set before projecting the payload. Use registered type key and schema revision to choose the renderer.
3. The owner query obtains the smallest allowed fields and bounded pinned dependencies. Use Dynamic Get for a query that expresses all necessary scope and shape. Use an explicit owner query when permissions, version selection, locking or a restricted projection cannot be expressed safely in the generated query. [JCB Dynamic Get workflow](https://github.com/joomengine/skills/blob/e7b8723397811772c85358e72ce91ab594785748/packages/workflows/dynamic-get.md)
4. PHP renders the scoped projection in native layouts, with encoded text, approved semantic markup and authorized media delivery. Render normalized math or approved notation through the configured visual and accessible renderer. Site assets add necessary behavior while preserving server-side validation and accessibility.
5. Form controllers apply the Joomla anti-forgery check for authenticated browser requests. They call the exact owner command with actor, scope, expected revision and idempotency key. The owner validates request body, references and invariants and returns a typed receipt or diagnostic. Administrator access alone gives no authority to invoke a different owner's mutation.
6. A native exam route rechecks its AssessmentDelivery and attempt policy. The server resolves exact item/interaction versions, authoritative deadlines and active lease. Persist accepted response evidence atomically before acknowledging it. Never place private evaluator settings, solution triggers or expected values in the candidate DTO.
7. Queue typed automatic marking or authorized human review from sealed evidence. Worker results return through the same versioned owner contract. Records calculates and issues results from approved evidence. Report cards and transcripts load official record revisions, including the applicable access and release checks.

A renderer missing from the installed registry marks the capability unavailable and supplies an operator diagnostic. The learner receives a safe explanation and can resume when the supported runtime is restored. An import cannot make a native PHP service execute a source script. Convert known semantics into a registered typed evaluator, preserve unsupported source evidence, or retain the package activity where its supported player can handle it.

## 4. From staged import to native publication

1. An authorized importer reserves protected storage and submits the archive through the transfer and scan pipeline. Persist its immutable evidence and selected format profile.
2. The selected adapter parses to a bounded intermediate graph. It reports each source object and relationship, typed conversion status, resolved asset and unresolved behavior. No adapter may write arbitrary database fields or import PHP into an executable path.
3. The review screen opens staged content and issues in the owning component. Render a safe preview of converted native types. Raw source and private expected values have separate permissions. Reuse the exact source identity map for retries.
4. Promotion calls the owning curriculum, assessment and storage operations. They create native identities and revisions, persist the verified typed values, preserve source evidence and resolve relationships. Record converted, retained-as-package, skipped and blocked cases with their exact dispositions.
5. An approved course draft is sealed and delivered through the native Joomla site. Its imported source remains available to authorized migration staff under policy. Subsequent editing uses native fields and review commands. A repeat import is an explicit transfer and reconciliation operation.

The [interoperability profiles](../interoperability/01-format-profiles-and-native-archive.md) define the supported intake and export capabilities separately. An accepted source profile does not automatically create a generator for the same format. Package playback, structured native conversion and downstream SCORM generation have independent acceptance evidence.

### Assisted authoring from source documents

A PDF supplied for authoring enters the curriculum source workflow as a protected exact asset. Approve its rights and extraction scope before using it for generation. A JCB-authored task plugin runs the registered extraction or invokes an approved extractor with bounded inputs. The owner records SourceExtractionRun, SourceRegion and their protected evidence. The source authoring workspace exposes authorized page and region previews, extraction issues and provenance without turning the private source document into a public lesson asset.

The author or permitted agent requests a CurriculumAuthoringRun against one exact draft revision and approved source set. Candidate content and assessments are staged as schema-checked authoring values. A teacher reviews the selected text, questions, marking semantics and provenance. Applying the accepted plan invokes native owner commands and writes exact SourceDerivationLink records. The approval, draft revision and apply receipt protect repeat operations. Course publication is a separate permission and version transition.

The same installed PHP owner APIs serve manual authoring, conversion promotion and approved generation. Parsing source archives or extracting text from a file can use approved workers with declared capabilities, resource limits and evidence. Native course presentation and authoritative academic writes remain in the installed Joomla extensions.

## 5. Export from native records

The default learner-delivery export is the verified SCORM 2004 fourth-edition profile `scorm/2004.4`. Enable it only after the profile passes its acceptance gates. SCORM 1.2 is an explicit compatibility choice for receiving systems that need it. If the default is unavailable or cannot represent a required feature, show the blocking issue and keep alternate profile selection explicit. Record the enabled edition, conformance scope and generator revision. This policy leaves other supported formats available and preserves the native content and runtime contracts. See the [export and round-trip profiles](../migration/06-export-projections-and-round-trips.md).

| Export objective | Profile behavior |
| --- | --- |
| Portable learner delivery | SCORM projection builds the approved organization, resources, assets, launch wrapper and edition API calls for the supported capability set |
| Editable curriculum portability | Native archive serializes versioned records, relationships and approved assets with identity and mapping evidence |
| Content and question exchange | Approved cartridge, QTI or document profile exports only its mapped content, activities or assessment semantics and reports coverage |
| Evidence or institutional records | Separate authorized report/roster/record contract. Learner responses, grades and private source assets are excluded from ordinary course exports |

An export begins with an authorized exact CourseVersion or library release. Resolve locale and profile, permitted assets and licenses, required content graph and exact activity/item/assessment versions. Generate a capability report against the declared profile. A blocking feature requires an approved change, a different profile or exclusion under the permitted policy. The generator does not silently replace a symbolic math evaluator, private rule, review workflow or unsupported interaction with superficially similar behavior.

Compile the approved projection into an isolated job. For SCORM, the released ZIP contains the profile's root manifest and portable browser resources. The receiving LMS supplies its runtime API. A self-contained export carries no Joomla session, privileged API endpoint, server-side PHP execution requirement, learner records or private source package storage locator. Features that rely on an authorized external service must be declared and tested against the profile. Treat any evaluator data bundled with a self-contained client resource as inspectable by the recipient. A private exam rule cannot be exported into inspectable scripts under an ordinary learner-delivery permission.

Validate the generated archive using the selected edition's package, manifest, reference, runtime and profile checks. Record input release digest, exact dependency pins, generator and schema versions, compatibility report, output byte hash and artifact storage reference. Repeat with unchanged inputs and verify the declared semantic digest and artifact reproducibility policy. Publish only after the export rights and artifact safety decision pass. The resulting package is a reproducible distribution artifact. A new export, withdrawal or conversion issue does not mutate the native curriculum.

## 6. Installed acceptance and handoff

| Acceptance slice | Demonstrate in the compiled and installed extension |
| --- | --- |
| Native authoring and playback | Draft an outline with shared prose, math, image, link and one typed quiz. Publish, enroll and read the exact learner release through Joomla site routes |
| Author and candidate separation | An author can edit allowed fields and review private criteria under separate privileges. Candidate HTML and API contain only the published safe projection |
| Relational persistence | Inspect real scalar columns and child relationships. Validate the same native flow, GUIDs, typed JSON and owner transactions on both supported database families |
| Source migration | Stage, review and promote an approved representative export. Reopen the resulting native content and confirm its supported question values and outcomes with synthetic cases |
| SCORM playback | Launch supported packages on the isolated browser origin, discover the right edition API, persist and replay a runtime receipt and surface any unsupported behavior |
| Export | Produce the exact default SCORM profile and at least one separately approved exchange format. Open outputs in authorized independent target tools and verify compatibility reporting |
| Source reproducibility | Import the editable blueprint, supporting code and plugin records into a clean authoring target. Recompile and install its packages without applying an emitted-output patch |
| Failure and recovery | Retry stale author saves, interrupted transfer and export, concurrent attempts and uncertain SCORM commit. Preserve accepted evidence and report exact unsupported scope |

Deliver the current JCB source graph, lock/provenance records, authorized plugin and Power definitions, compiled package, fixture manifest and installed verification report. Record source and runtime dependencies separately. A successful compilation establishes a built artifact. Supported assessment, export and standards claims require the corresponding installed behavior and reference-fixture evidence.
