# 03. Assessment and prose extraction

An XML course export can carry the lesson graph, scored problem definitions, unscored text and constructed-response assignments together. Extract the candidate presentation, interaction contract, marking contract and delivery policy independently. Retain source provenance in the private transfer records. Use the normal curriculum, assessment and records owners to build target drafts.

## Inventory and scope

Start from the approved course run and walk its selected published graph. Inspect every component node encountered in document order. Classify the node as an inline definition, an external package-relative pointer, a supported empty resource or an unsupported extension. A nonempty `openassessment` node inside a unit is a definition. A childless reference with no semantic body must resolve through the adapter registry. A missing extension body is an unresolved dependency, even if its placement, title and type are present. A file in a folder becomes migration evidence only when it is selected or reached. Count reachable published, selected draft overlay, unselected draft, unreachable and missing records separately. Do not use filename totals as a publication denominator.

Record exact source object key and occurrence in the protected transfer ledger. Imported XML may contain the problem markup and an escaped authoring representation in an attribute. The executable document form for a declared source profile takes precedence for understanding assessment structure. Preserve the authoring representation separately for review and possible lossless round trip. Do not parse it into a second copy of the same questions or render it on learner pages. Detect differences between both representations where a supported parser can compare them. A staged worksheet with prose and no scored control becomes a curriculum content draft after the reviewer verifies the intended behavior.

## Extraction pipeline

| Step | Extractor operation | Stage gate |
| --- | --- | --- |
| Preflight | Resolve package member and reject path escapes, external XML entities, DTDs, unreasonable parse depth and unsupported encodings. Scan namespaced tags, attributes, mixed text and child order. | A syntax or trust failure prevents parsed candidate content. Preserve issue code and private locator. |
| Classify | Mark public prompt nodes, interaction wrappers, presentation containers, private scoring attributes, targeted feedback, model solutions and execution-related nodes. | Unknown response syntax gets a protected issue and an explicit unsupported marker. |
| Partition | Walk in source order and build the visible prompt layout plus independent typed interaction, answer-rule and feedback records. | Every rendered control maps to exactly one stable interaction key. Private node ancestry overrides a public container. |
| Normalize | Check each form's supported family, aliases, layout, labels, counts and captured assets. Create portable score, retry and disclosure policies. | Any coerced or changed scoring meaning is declared and routed for review. |
| Validate | Reconstruct the complete candidate projection and separately construct grading fixtures from protected configuration. | Run accessibility, structural, visibility, execution isolation and score parity gates before publication. |

Use an XML tree interface that retains text before children and child tails. On every node process its content and then each child's tail at the child's original position. A solution removed from a table cell can still be followed by a public sentence or line break. Move the private subtree to the appropriate feedback rule and preserve the public tail in the cell. Avoid flattening descendant text into a string. That can move a correction inside the prompt, duplicate a label, erase an equation or collapse two different choice identities.

### Public prompt graph

Represent a mixed layout in `ItemVersion.prompt` as an ordered flat forest. Keep legacy leaf blocks for text, sanitized HTML, approved asset references and math. Use the additional typed container and interaction formats for interleaving. A container block identifies its semantic kind and optional parent block key. An interaction block identifies its `InteractionDefinition.key` and optional parent block key. Array order represents source document preorder. Parent keys refer to an earlier compatible container, and their order must satisfy contiguous subtree traversal. The same rule applies to approved `ItemTranslation.prompt` overlays. Preview and rendering use the same typed graph.

Map headings and public prose through the ordinary sanitized content profile. A table whose headings explain the relation between each response and its row uses table, row group, row, header cell and cell containers. Preserve the source reading order and bounded spans. Require clear header associations and valid accessible navigation. A layout table can become a responsive group while maintaining relative prose/control position. A translation can move display order if approved and preserve every interaction key. In the absence of explicit slots in an older native item, the existing renderer displays the item prompt then controls in authored order. The imported mixed-layout profile uses explicit slots so that later republishing cannot silently revert to that older rendering mode.

Require every placed interaction key to exist exactly once in the same version. An anchor for a missing key, incompatible parent, parent outside the graph, cycle, duplicated key or forbidden private content blocks publication. XML lists containing controls use list and list-item containers. Prose following an input can use trailing content or a subsequent public sibling. Preserve structural context wherever a question depends on a row heading, previous sentence or named region of a passage. Imported tabs and line breaks may affect readability but have no answer-token semantics unless a specific grading rule declares them.

Use up to 64 interactions and 128 criteria per item in this profile. Bound the layout forest to 2,048 nodes and depth 16. Validate before allocating renderer or scorer work. Preserve the shared submit boundary across larger worksheets. Splitting such a worksheet into separately scored and retryable items changes the contract. If a future source exceeds these limits, keep the original compound definition staged until a reviewed profile or an explicitly authorized transformation supplies equivalent behavior.

### Rich content and mathematics

Treat a question as content plus interaction. The public content adapter distinguishes rendered TeX, MathML, math-like text, inline or display marker and response grammar. A presentation delimiter is a markup cue, while a math grader's reference expression is protected data. Convert supported presentation forms into math leaves with accessible text or a reviewed equivalent. Keep superscripts, subscripts, typed tables and emphasis when they carry meaning. Preserve the entered number or expression string independently from its rendered mathematical preview. Sanitize escaped markup only at the declared XML-to-content decoding boundary. Never apply repeated entity decoding until the text looks like HTML.

Resolve local image and attachment references through approved AssetVersions and a safe public or private scope. Keep original dimensions only as bounded layout hints. Images in feedback rules remain protected even if other images in the same problem are public. Preserve image alternative text or flag missing equivalent content. Omit executable handlers, remote tracking requests and inline scripts from projections. Unknown presentational tags may yield a warning if stripping them preserves meaningful text and order. Escalate a warning when styling or an image expresses a distinction necessary to answer the question.

## Response/control translation

A source response declares scoring semantics and a nested control declares candidate input. Identify both before choosing a native family. Compatibility of a display control with a response on one input does not imply compatibility for a different nested control.

| Source response and control | Native family and scoring | Important distinctions |
| --- | --- | --- |
| `multiplechoiceresponse` + `choicegroup` | `single_choice` with list layout and one selected key | Correctness and per-choice partial points remain private. Accepted choices may exceed one even though the learner submits one. Preserve fixed options independently of display permutation. |
| `choiceresponse` + `checkboxgroup` | `multiple_choice` with a set-valued interaction | Choose exact-set, decision-count or halves rule from the declared profile. Record explicit empty selection separately from unanswered. Preserve compound hints as set predicates. |
| `optionresponse` + `optioninput` | `single_choice` with select layout | Child option syntax and legacy tuple attribute syntax are different parsers. A display label alone cannot identify an option across retries or translations. |
| `stringresponse` + `textline` | `short_text` with exact literal, case-insensitive literal or verified pattern rule | Keep ordered primary and alternate strings, source normalization and targeted feedback separate from candidate help. Preserve punctuation and casing rules. |
| `numericalresponse` + `formulaequationinput` or `textline` | `math` with numeric expression parser and numeric comparator | A plain text editor can still submit typed arithmetic. A trailing string is presentation by default and becomes a unit rule only when the source scorer checks it. |
| `formularesponse` + `formulaequationinput` | `math` with declared expression grammar, symbols and sampled comparator | A bounded source sampling profile is different from symbolic proof. Record domains, sample count, case policy and exact tolerance expression. |
| Missing, incompatible or multiple unhandled controls | Protected staged definition with unresolved compatibility issue | Unrecognized nested controls, renderer plugins and custom graders require explicit mapping and verification before activation. |

Within one source problem, use one reusable ItemVersion with an interaction and criterion binding for each independently scored response, unless the source definition explicitly groups several input controls under one criterion. A single assessment slot references that item. Preserve the submit boundary, attempt count, source point capacity and sum of criterion marks. A unit can contain several such assessment placements, each independently versioned and addressed. Native forms may use multiple slots when the source activity already had independently scoped submissions.

### Stable local identities

Map source response identity and each interaction/control occurrence to local immutable keys. Prefer a verified unique opaque source key when the profile treats it as identity. Many definitions have only order and structure. Derive a deterministic key from the source object identity and first admitted structural occurrence, then record the assigned key in the private map. Resolve choice IDs the same way using the control scope and original authored ordinal. Keep stable keys independent of label, answer flags, response text, displayed position and shuffled order. For example, two choices with identical visible text remain distinct when one is displayed first and the other second. An inaccessible duplicate may need a reviewed distinction to publish, but deduplication would silently change the answer set.

On reimport, compare the proposed correspondence and ask for review when inserted, moved or repeated responses make automatic matching ambiguous. Do not transfer keys by label similarity. Original aliases used by exported browser responses may differ from target keys and may depend on run-specific source naming. Attempt data can be mapped only with a verified immutable alias relation. Preserve option order and fixed positions in the form snapshot. For `ItemTranslation.labels`, keep translated names, descriptions and choice bodies bound to these same keys, regardless of translated display order.

### Labels and control suffixes

Use an explicit response label where one exists. Treat nearby presentation labels as label candidates only after checking structural relationship, such as a unique label in the same table cell or repeated question group. Record reviewed association with the canonical interaction and retain the displayed source prose. Where a visible label is missing, require a usable authored accessible name and reviewer approval. A deterministic context label such as “Response 2” can identify a draft control but is insufficient when several contexts would be ambiguous to a screen-reader user. Preserve trailing text such as a unit symbol, part-of-speech label or continuation of a sentence. Interpret input-size hints as capped presentation widths. Keep source `size` distinct from maximum response length.

For synthetic layout, one paragraph can introduce an invented rainfall log, two table rows can each contain a numeric input followed by a unit label, and a third row can contain one select control. Render the table with its row headers and maintain keyboard order. All three controls can share the same final submission. The protected criteria may use different matchers without affecting the public layout.

## Feedback extraction and disclosure

Keep a versioned private ItemFeedbackRule for each required feedback block or ordered hint. Use a stable rule key, scope, source order, typed trigger and sanitized rich content. Scope rules either to the whole item or an exact interaction/criterion. Classify `demandhint` and its ordered `hint` children as on-demand help. Choice and option hints attach to an exact selected key. A compound checkbox hint matches a set. Correctness and textual hints retain their match strategy and precedence. An alternate answer's associated hint binds to the actual matched alternative. A `solution` nested under a response carries response scope. A solution elsewhere in a table or problem remains problem scoped unless the verified source profile assigns it more specifically. Record rather than guess uncertain positional attachment.

Extract and quarantine source answer keys, scoring expressions, private rules and hidden feedback before constructing candidate content. Candidate-facing explanations may be computed or presented only through authorized review or hint paths after the relevant field-specific gate. Published item and bank reuse checks prevent an exam answer from leaking through an unrelated practice placement. Correctness indicator, points, hints, alternate feedback and model solutions are separate field permissions. Apply the resulting restrictions to HTML, accessible projection, API, assets, exports, notifications and caches. Never ship a hidden DOM panel containing the unreleased answer key.

## Constructed response and rubric extraction

Inline constructed-response definitions carry one or more prompts, one rubric and ordered workflow steps. Parse direct child workflow and rubric structure, rather than extracting from display labels or directory names. Attach all declared response prompts to one ItemVersion and one shared RubricVersion so that each criterion can judge the specified evidence together. Map the requirement for written response and attachment response independently. For each enabled channel, preserve whether it is required or optional. A required uploaded artifact belongs to the file interaction and is validated at finalization. A disabled text channel does not create an empty obligatory text field. If both channels are optional, apply the source's approved submission-presence rule and flag any mismatch. Preserve allowed media families, declared attachment multiplicity and math entry policy subject to scoped upload controls.

The constructed-response profile uses one `long_text` interaction per enabled written prompt and an item-level file interaction when attachments belong to the submission as a whole. A supported rich text editor uses the same bounded sanitized evidence projection that the marker will see. An unsupported rich mode may stage a plain-text compatibility proposal with an explicit fidelity issue. Do not silently strip meaning-bearing formatting or LaTeX from evidence. Rubric exposure during response is separate from rubric use by authorized markers. Restrict rubric visibility while responding when the imported policy does. Candidate self-review may receive its approved rubric only during its independent review phase.

Map rubric criteria by stable source keys where available, otherwise by first admitted ordinal correspondence. Map the criterion description and feedback mode, plus ordered level identities, labels, descriptors and points. Retain general feedback prompt and default marker guidance separately from public candidate prose. Sum criterion maxima to the rubric maximum. A criterion with one zero-point level can collect staff feedback without earning marks. Retain the level or represent it under the reviewed feedback-only mode. A rubric consisting only of feedback-only criteria retains submission and marking workflow without contributing numeric points. A native rubric must not fabricate a passing grade from a zero possible total.

| Workflow definition | Target authorities | Publication test |
| --- | --- | --- |
| Required staff review | AttemptSubmission, MarkingAssignment, ItemMarkRevision and AssessmentFeedbackRelease | Assigned staff can see sealed work and the frozen rubric. Candidate sees approved feedback only. |
| Self review before staff review | DeliveryPolicyVersion.self_review, SelfReviewRevision and then scoped staff marking | Preserve self-review window and whether it is required. Self-review never replaces the accepted staff mark. |
| Source permits staff bypass | Approved self-review bypass setting with recorded marker action and reason | The default still waits for a required self-review. A source-parity profile may let authorized staff explicitly close it with bypass provenance. |
| Peer, training or external review step | Existing peer-review entities or protected unsupported workflow | Require a verified mapping for step order, eligibility, scoring authority and failure recovery. A pointer alone cannot activate a workflow. |

The authoritative constructed-response acceptance records the latest accepted staff mark under the imported workflow policy. Peer and self review remain separate evidence. A migration must distinguish "step exists", "step required to finish learner participation", "step produces official marks" and "staff override bypasses another step". Review an inherited due time separately from the self-review period. Map a hidden rubric, empty optional comment and disabled candidate attachment channel deliberately. Review source team-mode configuration only where present and resolved against the offering group definition.

## Executable and unresolved material

Detect `script`, custom responder attributes, dynamic references, JavaScript input, external grading endpoints, executable documents and plugin kinds. Record signature classes in the protected ledger, including language marker, declaration dependencies, variable interpolation positions, reachable input or output channel and required external state. Do not import them as active code. Classify literal currency markers, escaped dollar characters and math delimiters before identifying a dynamic placeholder. Even a syntactically valid placeholder remains unresolved when its definition is absent. Static source inspection may suggest a mapping to a registered deterministic VariantProfileVersion or MarkingRuleVersion. Acceptance requires independent test fixtures and review. A retained original is an opaque restricted TransferArtifact and is never sent to the renderer or evaluator as code.

Before handoff, reconcile every encountered definition as mapped, mapped with accepted presentation difference, blocked for scoring or accessibility, external dependency, or prose-only. Link each proposed record to the protected source locator and versioned adapter. The private acceptance report separates unknown from missing and structural import from score parity. All examples and fixture inputs shipped with the design are invented.
