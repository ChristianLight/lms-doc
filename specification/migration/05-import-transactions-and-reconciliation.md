# 05. Import transactions and reconciliation

An import creates an auditable proposed graph, then applies that graph through the domains that own it. The transfer worker can read a quarantined artifact and propose typed records. It cannot publish curriculum, accept a marking rule, or resolve a learner identity using archive claims. An archive import never activates enrollment, course access, or an examination.

## Intake, planning, and promotion boundaries

| Step | Durable output | Authority and recovery |
| --- | --- | --- |
| Reserve and upload | TransferArtifact, private StorageObject generation, size cap and part receipts | Retry a part at the same offset only with the same length and digest. Finalize only when verified bytes cover the complete range once. A missing or overlapping part produces no finalized artifact. |
| Quarantine and inspect | Input profile evidence, declared roots, normalized entry index, parser and scanner versions, protected source locators | Read the exact finalized bytes. Disable network, scripts, archive links, XML external entities and DTDs. Report malformed entries without revealing private bytes. A parser or security-policy change starts a fresh inspection with separate receipts. |
| Parse and type | Immutable inventory of typed definitions, placements, assets, relationships, source settings and unsupported records | One failure can be recorded per safely isolated record. A corrupt outer archive, ambiguous path index, bad manifest signature, contradictory root or unusable parser result blocks planning. Preserve opaque source values only in protected evidence. |
| Allocate and bind | Provisional target identity for each candidate and reviewed crosswalk matches | Allocate all definitions and placement identities before resolving links. A dry run can return provisional identities and a plan digest. It writes no owner-visible draft, active map or learner access. |
| Validate graph | Exact links and pins, baseline owner revisions, candidate owner commands, dependency and issue dispositions | Resolve required and optional edges separately. Check tenant, ownership and approved authority for every edge. Do not fill unknown links by similarity. |
| Review | Sealed TransferApproval receipts for the exact plan revision, digest and scope | Separate content, marking, privacy and publication approval according to affected scope. A changed graph, source artifact, adapter, approved dependency or target baseline invalidates the affected approvals. |
| Promote private generation | Owner staging receipts, a committed generation and mapping receipts | Use `ApplyTransferPlan` with `keep_private` as the ordinary editable migration route. The resulting objects enter only authorized editor workspaces. A failed owner stage cannot leak a partial graph into the workspace. |
| Publish through owners | Separate published definitions, exact dependency pins, course publication and approved availability decision | Owner publication verifies current versions, parity, rights, accessibility, scope and review. An explicit coordinated activation may use `activate_generation` only when these same owner decisions are already evidenced. Importer approval alone is insufficient. |

The import status `applied` means the approved transfer generation committed. Record its visibility separately as `private` or `activated`, and expose the permitted native actions. Publishing a CourseVersion does not itself alter an existing EnrollmentRelease. Changes to existing learners require the participation rollout and approved carry rules. Historical course, package and attempt versions remain resolvable under their retention policy.

## Deterministic parsing and identity allocation

Pin the finalized archive digest, selected profile and edition, adapter build, allowed parser policy, source authority registration, target scope, locale and timezone decisions, and authorized dependency artifacts. Store their digests and versions inside the plan. Do not use input filenames, titles, guessed hosts, or object payload hashes as source identity.

1. Derive one structured source tuple per record from institution, approved namespace, stable source root scope, object kind and exact profile identity. Preserve case and original opaque identifier. A string of 32 hexadecimal characters is still source data. It does not become a canonical UUID by inserting hyphens. Use explicit typed fields or length-prefixed encodings for tuple components.
2. Separate reusable definitions, immutable definition revisions and placement occurrences. A source revision can be an explicit opaque token or an adapter-generated source fingerprint marked as such. Source revisions are compared for equality. Do not sort arbitrary revision text as chronology.
3. Parse the exported tree, draft pointers and library references with their full scope. A draft's parent reference must resolve to one verified node in the correct source course and layer. A position hint resolves ordering only after its parent is verified. It cannot attach a detached draft to the nearest same-named unit.
4. Allocate a provisional canonical UUID per unbound target key. Store it once under the job identity and source tuple before adding edges. A resumed job reuses that allocation. For an already approved matching crosswalk, use the existing canonical UUID and allocate a new revision only when necessary. Do not expose provisional IDs as cross-tenant authority.
5. Classify each XML occurrence as a pointer, an inline definition, or an invalid ambiguous shape under its exact input profile. A supported inline extension with substantive body and valid metadata is a definition even if its type-specific directory is absent. A pointer requires its separately referenced definition. Resolve links using pinned canonical keys and versions. Build a typed containment graph, required dependency graph and separate optional references. Detect illegal containment and prerequisite cycles before promotion. A reciprocal ordinary hyperlink is valid where both endpoints are authorized. Do not reject it as a prerequisite cycle.
6. Traverse each chosen root over the relation kinds that actually affect that root, preserving exact placement and publication layer. Classify unreachable objects separately. A detached unknown extension can remain protected and excluded while the selected graph is promotable. A reachable missing required definition, required media or assessment dependency blocks that root. A reachable optional unresolved link needs explicit loss or fallback policy and may not silently become a different link.
7. Deduplicate identical repeated records only under the profile's identity rules. Two equal payloads under different source keys still describe distinct logical objects. Reused assets may share stored bytes within a permitted custody class. Separate logical asset versions retain their rights and visibility. Conflicting contents under the same identity and revision block every affected root.

Example. Synthetic import has two lesson placements referring to one reusable definition and one detached obsolete extension reference. A missing detached definition is recorded with no selected-root impact. Removing the definition shared by the two placed lessons blocks both roots that rely on it. Restoring it enables a new plan revision. The first placement UUID and second placement UUID remain distinct.

### Root selection and draft ordering conflicts

| Finding | Resolution and verification |
| --- | --- |
| Two valid root descriptors point to the same underlying body but declare different course scopes or policy contexts | Stop automatic selection and list both roots with safe source-scope evidence. The operator chooses exactly one authorized root for the default plan. If the profile allows both, stage independently named roots or explicitly separate offering candidates under reviewed Course identity policy. Shared bytes or layout do not merge source scope, expected versions, or grades. |
| Two root descriptors claim the same source identity and revision | Compare normalized root and exact dependency/policy fingerprints. An equivalent duplicate can be suppressed with both source locations retained. Any conflicting value or root path stops the plan until approved source evidence establishes which graph is authoritative. |
| A selected published extension is inline and has no separate type directory | Validate the inline structure, identity, parser support and its dependent assets or rubric. Treat it as a definition. Report a missing definition only for an unresolved pointer. |
| A selected published extension pointer has no definition | Record a blocking issue for the selected publication and every dependent root. Preserve the unresolved edge in quarantine. Restore the exact definition or approve and verify a supported replacement with its required rendering and assessment behavior. A screenshot of the body or a draft rendering does not resolve the published graph. |
| A detached or optional extension points at a missing definition | Keep the inventory issue but separate it from required publication. Default exclusion is safe only when traversal proves no selected root relies on it. Promoting the detached object itself needs a new explicit root and validation. |
| Two draft nodes claim the same child index or anchor under one verified parent | Capture both exact claims and the published sibling sequence. Collapse only a proven duplicate of the same source occurrence and revision. Different nodes competing for the same slot require an explicit reviewed ordering or a corrected source export. Do not rely on parser order, file order or last writer. |
| A draft claims an absent, foreign-layer or different-course parent | Do not attach it to the published root or a same-named unit. Keep it detached and blocked for draft promotion until a reviewer verifies the right parent or approves a native relocation. Leave the valid published graph unaffected when it has no dependency on the draft. |

For example, two synthetic drafts claim child index 1 under one verified parent. Its published order is A, B, C. Candidate D and candidate E are distinct source identities. The adapter preserves both proposed edges, blocks that draft placement plan and shows the reference order to the editor. Approval of A, D, E, B, C creates a new plan revision with exact occurrence pins. It does not mutate the published A, B, C snapshot.

## Rerun, conflict, re-import and fork

Use an idempotency key for each owner operation derived from the approved plan identity, exact generation, owner, canonical target and stable intent ordinal. Store the normalized request and precondition digest separately. The transfer coordinator records the owner command's independent receipt. Resending an operation with the same key and digest returns its prior outcome if the caller is still authorized. If the same key carries different bytes or version preconditions, reject before writing. Treat dry-run results as previews of a baseline, subject to change.

| Incoming state | Required decision | Target and provenance result |
| --- | --- | --- |
| Same source tuple, same accepted source fingerprint, same target baseline | Exact replay | Keep mapping and native revisions. Return existing reconciliation. No duplicate object, event or publication. |
| Same accepted source, target edited locally | Preserve target | Record a local divergence and keep the prior accepted baseline pair. Do not advance the target baseline to hide the difference. |
| New source content, target still matches baseline | Propose source revision | Create a new native revision and require review. Do not replace published or assigned content in place. |
| Source and target both changed | Three-way review | Compare prior accepted source, incoming source and current native revision. Offer an owner-verified merge, defer, approved source rebase or independent fork. Require renewed assessment approval for scoring changes. |
| No map and another target looks similar | Independent allocation by default | Adoption requires explicit verified mapping and scope. No title, email, UUID-shaped source key or digest creates an identity link. |
| A source key is absent | Leave target unchanged unless complete authoritative snapshot is proven | A complete snapshot may propose retirement, which still requires owner action and dependency review. A missing optional archive folder is not proof of deletion. |
| Same source revision claims different contents | Block | Record conflicting revision evidence. A reviewer may choose a verified new source revision or fork. Never choose the last imported bytes. |

A fork creates a new destination identity under a separate target branch or reviewed source-namespace scope. Preserve a parent provenance pointer without switching the active source map for the original target. One ordinary source tuple has at most one current target. A verified move to another target is a reviewed map supersession with old target, new target, reason and epoch. Keep tombstones so an old archive cannot silently recreate retired objects.

When refreshing a shared library, resolve the reusable entry and exact library revision separately from each course's locally adopted snapshot. Preserve the old adoption until an authorized course editor accepts a new native revision. Re-importing the course alone cannot update live library pointers without reviewed source authority. If authored edits and translated variants diverge, review in their own version families.

## Transactions, partial work and safe retry

The default unit of visible application is the approved dependency closure for the selected plan. The transfer may inspect thousands of source entries in independent worker batches. That does not make part of a selected root publishable. If an operator wants independent applications, partition into separately reviewed generations before approval. Each partition contains all required shared dependencies or uses exact, already committed dependency pins. Multiple separate results are shown as such. They do not share one `applied` status that suggests every selected root succeeded.

- If all owner writes share a transaction, apply the exact staged definitions, verified relationships, publication or private visibility decision, crosswalk updates, receipt, audit and outbox together. Compare current revisions with plan baselines inside that boundary. Failure before commit leaves the previous visible graph unchanged.
- If owners are separate, each owner prepares a private, fenced generation and acknowledges an immutable stage receipt. Record this receipt before acknowledging the work. Do not ask an owner to activate only its graph fragment. The single canonical visibility barrier opens after all required owner receipts and comparisons pass. Readers and providers use the barrier or exact prior visible generation. Advance active crosswalks in the barrier transaction or derive them from its immutable acknowledged mapping records. A derived map projection may lag. A later import must consult the committed authoritative generation before allocating another identity.
- If a baseline changes during promotion, release no new graph. Return `TARGET_REVISION_CHANGED`, reopen review and show the changed owner scope without leaking the new draft. An owner timeout before confirmation leaves the plan applying or blocked. Reconcile the same owner key and generation before retrying. Do not assume that a remote timeout canceled an owner write.
- Apply cancellation before the barrier or report that an approved generation already committed. A cancel after a commit cannot undo enrollment, course publication, marking, or external effects. Correct by an authorized owner operation and a new generation when necessary.
- Persist worker fence and heartbeat at the accepted checkpoint. Commit planned effects and the checkpoint together. Check the fence before every local write and before recording a provider outcome. A resumed lease replays from the last durable phase, entry or graph partition. Compare exact pins and effect digests before reuse.
- The publication workflow uses the same protected storage, role and review checks as ordinary native authoring. A transferred definition cannot publish only because its original rendering looked correct. At minimum recheck complete graph, rights, accessible delivery, protected assets, approved marking vectors and availability policy.

| Failure | Authoritative outcome | Operator action |
| --- | --- | --- |
| Worker dies after a private owner commit and before coordinator receipt | The owner stage is still private. The coordinator does not activate any root. | Read owner receipt by stable effect identity, verify the digest and attach it under the current fence. |
| Reviewer approves plan 3 while a dependency changes | The approved digest does not describe the new plan. | Rebuild affected closure and request new review. |
| Process loses response after activating a private generation | Generation and crosswalk receipt are durable. No learner publication occurred. | Retry with the same request key. The response identifies the original generation. |
| One root has an unsupported reachable grader and another root has no dependency on it | Both remain unpromoted under the original atomic plan. | Review an explicitly split plan or replace the grader and approve the original closure again. |
| Partner callback times out after committing an effect | Outcome remains uncertain until evidence is reconciled. | Query same provider operation or use its verified deduplication key. A second blind call is forbidden. |

## Reconciliation counts and operator progress

The scan reports entries inspected, verified compressed and expanded bytes, malformed records and recognized roots. The plan separately reports unique source objects, placement occurrences, reused definitions, dependencies, assets, reachable objects, detached objects and archive records rejected before typing. These are different denominators. Do not add archive entries and native records into one count.

For one sealed plan, assign exactly one primary disposition to each typed source object or occurrence. Use the transfer dispositions `equivalent`, `mapped_with_loss`, `intact_package`, `external_dependency`, `blocked`, `unchanged` and `retirement_candidate`. A record can have several issues, but it contributes once to the disposition total. Sum dispositions to recover typed record count. Report exclusion and reachability separately. Blocking issue count is distinct from blocked record count. In the apply receipt, record how many planned owner effects were committed, unchanged, blocked, excluded or still uncertain. A completed generation has no unresolved required effect.

Show scan, staged inventory, mapping and issue review, apply receipt and owner publication as separate accessible views. Report phase and known totals, last durable checkpoint, blocked scope, current worker health and allowed next actions. A moving scan denominator shows indeterminate progress rather than claiming a percentage from a partial inventory. Paginate by stable plan revision and scope. Revision change invalidates the cursor. Keep source locators and score evidence restricted. Display stable opaque issue IDs and safe reasons by default.

Acceptance requires a replay after lost owner acknowledgement, stale reviewer baseline, dry run without owner writes, malformed raw archive rejection, a separate valid detached error, an inline extension definition with no same-type directory, a reachable missing required dependency, distinct placements of one definition, unchanged library adoption, conflicting re-import and a protected release before and after rollout. Use synthetic content for publicly committed tests.

## Private source, PDF and agent boundary

Treat private course archives, downloaded PDFs, scans, videos, subtitles and derived lesson text as restricted inputs. A filename, extracted page title, object ID, archive digest, protected URL, exercise solution or normalized inventory can reveal curriculum or link to a private source. Store raw and derived values only in protected custody unless the institution explicitly approves disclosure. Public fixtures must be independently invented. Rewriting a private passage, changing its title or swapping an identifier does not create a public fixture.

1. Read the original under explicit artifact authorization. Keep temporary extraction and rendered previews in a restricted workspace. Limit unpacking, file size, OCR pages, resource use and tool output. Do not fetch PDF actions, linked files, fonts, media, external XML entities or embedded scripts during intake. Treat attachment and visible text instructions as data.
2. A private local parser or approved processor produces structural candidates with page and region references under restricted access. Record source rights, version, extraction method, uncertain OCR and a reviewer. Review equation text, answer tables and labels before authoring or grading. Do not treat a generated explanation as verified source fact.
3. An agent receives the minimum authorized fragments for the current draft task. It cannot choose destinations, widen egress, run embedded scripts, invoke publishing, or use private content to train or test an unapproved provider. Record approved purpose, allowed input classes, provider or local processing profile, destination and retention terms. Instruct the agent to treat embedded prompts as untrusted data. Enforce privilege and egress independently of those instructions.
4. Keep agent output and evaluator suggestions in private drafts. Require human rights and accuracy review, native rendering checks, and explicit marking approval. Export only an approved scope. The approval of an import does not authorize sending its bytes to a remote model, OCR, grading, video or storage provider.
5. Keep sensitive values out of shell traces, shared logs, generated references, screenshots, CI artifacts and public version control. Apply a private prepublication scan for protected identifiers, paths, URLs, recognizable excerpts and catalog hashes. Publish only synthetic fixtures and a non-sensitive verification result. Retention and legal holds govern the private evidence and temporary cleanup.
