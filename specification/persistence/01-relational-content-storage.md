# Relational storage for native curriculum

A native course consists of independently addressed records with validated values. A published release pins exact records and relationships. A lesson is editable as structured content after import. An exchange package preserves the source and conversion evidence or delivers an exported projection. The native authoring and learning paths read the same canonical curriculum through different authorization and presentation contracts.

The six [domain catalogs](../README.md) remain authoritative for names, fields, lifecycle and numeric bounds. This chapter maps their existing records to scalar columns, separately persisted rows, bounded structured values and protected bytes. It introduces no required entity. The [database profile](02-mysql-mariadb-physical-contract.md) gives one physical implementation. The [runtime composition chapter](../joomla/07-runtime-composition-and-format-boundaries.md) maps the same data to native Joomla screens.

## 1. Choose the unit of persistence

| Data behavior | Storage decision | Course and assessment examples |
| --- | --- | --- |
| The object has an identity, independent version, scope, lifecycle or access check | One owner row with typed references to other owner rows | Course, CourseDraft, ContentNodeVersion, ContentPlacement, ItemVersion, InteractionDefinition, MarkingRuleVersion, RubricCriterion, AssetVersion |
| The value filters, joins, sorts, participates in a lock or has a uniqueness rule | A typed scalar column, with owner validation and an appropriate index where needed | Offering identity, parent placement, sibling scope and order, item version, interaction key, family, evaluator release, assessment maximum |
| The value is a bounded subtree interpreted and replaced with the enclosing revision | One validated structured column with an explicit schema and canonical encoding | One localized rich text AST, one interaction's option list, a completion gate, typed evaluator settings |
| Bytes are large, must be scanned, or are served through file rights | Protected storage identified by a typed relational pointer and verified digest | Video, caption files, scanned source backup, attachment, immutable provider capture |
| The data can be rebuilt from authoritative rows | Derived read model, digest projection, manifest or export | Outline tree in memory, search snippets, rendered HTML, source impact preview, SCORM archive |

Use SQL for stable relationships and the scope predicates that protect them. Use typed structured values when the internal elements have no independent write, access or retention contract. A flat name/value table for unrelated course fields has no type-specific owner and obscures relationships, uniqueness and access rules. Model a newly independent object as an actual owner record after agreeing on the lifecycle, querying and review behavior that requires it.

A structured value has a named schema and resource bounds. A writer decodes once, rejects duplicate object names, validates the tagged type and ranges, resolves every typed reference and computes the canonical digest. Unknown type keys and schema versions stay staged until a compatible adapter exists. Preserve semantic order in arrays such as prose blocks, choices and outline siblings. Use the owner-declared canonical ordering for sets, object keys and provenance before hashing. Exact decimals remain canonical strings where required by the catalog. See the [native archive serialization rules](../interoperability/01-format-profiles-and-native-archive.md).

## 2. Native outline and publication

| Owner record | Scalars and references | Compound value or evidence | Access path |
| --- | --- | --- | --- |
| Course | Institution, owning unit, normalized business code, locale, title, visibility, state, revision | Small summary under the course field contract | Unique institution and normalized course code. Direct lookup by application ID |
| CourseDraft | Course, exact base CourseVersion when present, owner principal, revision, state, approved digest, default locale | Draft digest binds the proposed graph | Load the authorized draft and compare its current revision before edits |
| DraftPlacement | Exact draft, stable placement key, parent key, derived sibling scope, position, kind and visibility, exact definition and rule links | Each occurrence has its own row. Content is shared through version references | Unique draft and placement key. Unique draft, sibling scope and position |
| DraftReview | Exact draft and reviewed revision, digest, reviewer, decision, effective time | Bounded issue list | Look up the review for the exact digest that is being published |
| CourseVersion | Course, source draft, version sequence, draft and manifest digests, publishing principal and time, availability state | Durable canonical publication manifest at its authorized locator | Unique course and version, and unique course and approved draft digest |
| ContentPlacement | Exact CourseVersion, placement key, exact parent occurrence, sibling scope, position, kind, linked content/activity/rule revisions | One row per occurrence, even when siblings reuse the same node version | Unique course version and placement key. Unique course version, sibling scope and position |
| EnrollmentRelease | Enrollment and the learner's exact CourseVersion | Effective assignment and historical lineage | Resolve the single effective assignment within the enrollment owner |

`CourseVersion.manifest_locator` points to the immutable publication envelope. Its digest binds the ordered relationships and version pins. Query the relational placement rows for native navigation, dependency validation and authorization. Use the frozen envelope to verify, reproduce and transfer that release. A discrepancy between the stored envelope and the reconstructed graph is an integrity error. It blocks serving or exporting the affected graph until the owner reconciles the exact publication and evidence.

A stable placement key identifies the same instructional occurrence across compatible drafts and releases. Its exact row identifier identifies one revision's occurrence. A reusable node identity identifies the thing edited. Its version identity selects the text and references used at runtime. Link and transfer APIs carry the identifier appropriate to each purpose. Numeric host row IDs never substitute for these identifiers.

### Edit and seal

1. Resolve CourseDraft, actor and institution. Require the expected revision and the relevant author or importer permission.
2. Validate the entire staged placement tree before changing rows. Check one occurrence per placement key, valid parent within the draft, supported parent and child kinds, acyclicity and sibling count and order. Derive the non-null `sibling_scope_key` as `root` or `parent/` followed by the canonical parent key. Store the course draft's stable parent key. Resolve a published parent to the exact occurrence row in the publication.
3. Resolve each referenced version and rights scope. A structural or renderable content placement points to ContentNodeVersion. An activity placement points to ActivityVersion. Where permitted, it also pins LearningRuleVersion. Reject inconsistent kind/link combinations. A published required placement cannot contain an unresolved executable source object.
4. Write the desired placement changes and one next draft revision atomically. On a reorder, avoid transient unique position collisions. Use the [transactional reorder profile](02-mysql-mariadb-physical-contract.md#concurrent-reordering-without-changing-ids) for this database deployment or an equivalent atomic strategy. Retain occurrence keys and preserve protected references. A malformed form or omitted PATCH field never means an empty child list.
5. Publication locks the approved draft at the reviewed digest, resolves the version closure and creates CourseVersion and exact ContentPlacement rows. Verify all internal links in that exact graph. Persist the canonical manifest digest, receipt and outbox before acknowledging publication.
6. A new author edit seals a new node or activity revision. Existing releases still read their pinned versions. CourseOffering and EnrollmentRelease determine when the new publication becomes effective. Assessment attempts preserve their exact version pins across a later enrollment rollout.

### Resolve native links

Store a typed internal link destination as a stable placement key and optional anchor. At publication, resolve it in the exact CourseVersion. A reused text block can occur in many course releases, each with its own resolved destination. Two occurrences of the same definition retain distinct route and progress context. A learner click authorizes the resolved destination again under the current EnrollmentRelease. Authorization can hide the destination or return an explanatory locked state according to policy. An anchor references a stable block ID in the destination's selected locale, with an approved fallback or a publication diagnostic for a broken anchor.

Store a typed external link as its validated HTTPS URI and descriptive label. Leave the label and URL distinct. Do not persist an HTML anchor element or public signed media link as the destination identity. Browser navigation follows the allowlisted scheme and site link policy. Server-side preview probing is a separate authorized operation with bounded retrieval and redirect checks.

## 3. Structured content and exact media

| Canonical owner | Relational fields | Validated value | Write boundary |
| --- | --- | --- | --- |
| ContentNode | Institution, unit, type key, creator and time | None required for the editor's content body | Create stable identity before sealing its first revision |
| ContentNodeVersion | Node ID, revision, digest, author and time | `payload` with `type_key`, `schema_version`, `default_locale`, and ordered `variants`. Each variant has locale, title, body, review state and optional source digest | Seal after schema, scope, accessibility and dependency validation. Pin exact rows in the outline |
| Activity and ActivityVersion | Activity kind, owner scope, revision and exact AssessmentVersion or PackageVersion where applicable, digest and author | Typed locale instructions and kind-specific configuration with declared signals | Resolve the one runtime for the kind. Attempts and learner outcomes use separate records |
| LearningRuleVersion | Institution, course, stable rule key, revision, visibility and continuity, digest | Bounded typed `gate` and `completion` values under the [rule schema](../curriculum/learning-rule.schema.json) | Reject cycles, untyped operators and incompatible prerequisite scope before publishing |
| Library and LibraryEntry | Scope, business keys, sharing and rights, title, entry kind | Bounded taxonomy tags | The reusable container has its own lifecycle and author permissions |
| LibraryEntryVersion | Entry ID, revision, exactly one pinned content, activity or template release target, license and digest | Protected path list | Publication seals the target and reusable policy. Course consumers adopt a version |
| LibraryAdoption and TemplateMergePlan | Target draft and placement, source entry revision, expected draft revision and plan state | Bounded source map or reviewed change list | Reviewed synchronization issues a new target draft revision. Source updates leave published consumers pinned |
| Asset and AssetVersion | Ownership and kind, exact asset revision, digest, bytes, type, file name, rights and safety state. Managed asset references StorageObject and StorageScanResult. Hosted asset references ExternalResourceMap | Delivery-safe media metadata where the content schema permits it | Verify digest, rights, scan or provider revision before linking. File bytes stay under protected storage |

The [learning definition schema](../curriculum/learning-definition.schema.json) owns the exact per-type shape. An editor presents the discriminated controls for a structural block, rich paragraph, image, document, video, audio, external link, internal link or registered activity. It sends a complete versioned value rather than editable source XML. A rendered HTML fragment is derived at read time from the content variant. The assessment prompt's existing bounded `sanitized_html` leaf is a supported presentation fragment under its own validation profile. It does not carry its version, placement, file permissions, answer values or grading logic.

### Rich document fields

The ordered rich document body contains typed blocks with local IDs. Paragraph runs hold literal text and formatting, typed links or math. Lists, callouts and quotations recursively carry child blocks under the depth limit. A table stores typed rows and header relationships. A media block carries the exact AssetVersion GUID. Store such small semantic trees as one value owned by the exact ContentNodeVersion. An edit produces one new revision rather than adding an owner row for each text run, bold mark or equation token.

Keep locale order and default locale deterministic. Verify locale uniqueness after normalizing the language tag and require the default variant to exist. Preserve stable block IDs across semantically compatible edits. A title used for the authoring picker can be read from the approved default variant. If a deployment needs an indexed title or language list at scale, store a derived projection and rebuild it from the authoritative payload. A projection failure leaves the owner version and digest unchanged.

### Typed dependency extraction

A reference resolver walks only schema-declared fields. It returns a bounded list of type, field pointer and target identity. Examples include an image body's `asset_version_id`, a rich block's `asset_version_id`, a video's source, caption and transcript assets, a document's alternate content version and a link's stable target placement key. Never scan all strings for something resembling a UUID. Resolve `external_resource_map_id` only under a compatible provider registration and pin its provider version. Raw source markup, provider URLs and signed URLs do not establish ownership or runtime access.

The resolved set for a reviewed course participates in publication and export manifests. Runtime media queries still check the exact AssetVersion, current safety state and actor scope before delivering it. If a managed asset has a scan decision for different bytes, deny the asset and report an integrity issue. If a hosted revision can no longer be retrieved or confirmed, block approved capture or display the declared accessible alternative. Replacing bytes creates another AssetVersion. It cannot silently change the version cited in a course or sealed assessment evidence.

The required Platform reference projection consists of ContentReferenceSet and its ContentReference entries. A complete set represents one exact owner revision and context even when it contains zero entries. The set pins `source_digest`, `projection_profile`, `generation`, `entry_count`, `entries_digest` and the current coverage state. Its uniqueness key is institution, source kind, source version and non-null context key.

| Context | Keys and version guard | Entries |
| --- | --- | --- |
| Definition | `context_kind=definition`, `context_key=definition`, fixed source kind resolver and exact source version | Exact typed asset, content, activity, assessment, package or provider reference. An internal link carries the deferred stable `target_selector` |
| Placement | `context_kind=placement`, source placement GUID as context key, exact `course_version_id`, `source_placement_id`, `definition_set_id`, `definition_generation` and `graph_digest` | Resolve each required stable selector to the exact `target_placement_id` within that publication. A changed definition generation invalidates the corresponding binding |

Each ContentReference has `set_id`, `generation`, a semantic `reference_key` and digest, diagnostic RFC 6901 `field_pointer`, relation discriminator, exact typed target or selector, and publication requirement flag. Exactly one target slot is populated under the selected relation. Preserve the optional validated anchor separately. Enforce unique set, generation and reference key digest, and compare the full key on conflict. Reverse indexes lead with the exact typed target and join to the corresponding set. Never return inactive generations as current.

Use existing stable block or interaction keys and a declared relation role where one independently identifiable source reference exists. For repeatable embedded references without their own key, derive a bounded semantic key from the owning locale, nearest stable source block, relation role and canonical target and anchor under the projection profile. An encoding can use `r1/`, the lower-case SHA-256 of the canonical tuple and a deterministic suffix for identical repeated references. Compare the full typed tuples while building the set and fail on any distinct tuple with the same encoded key. This preserves key meaning when unrelated text changes position or translated labels change. A revision with a changed target is a changed semantic edge. The positional field pointer remains exact for diagnostics in that revision.

A scalar rule or version link already in a canonical row keeps that row as authority. A projection entry describes its indexed reference and never grants ownership, retention permission or access. A renderer, exporter or reviewer resolves the exact target through its owner and checks the current policy. `RefreshContentReferenceSet` and `InvalidateContentReferenceSet` are owner-internal operations. `ReadContentReferences` is an authorized read projection. Never accept user-supplied rows as proof of coverage.

The owner command captures one complete generation from one verified source revision. Write the source revision and its required reference set and entries in the same database transaction where the owner contract supports it. A background reconciliation can rebuild and compare a complete set. It records the exact source watermark and denies destructive use while stale or incomplete. It never mistakes zero reference entries for completed extraction without the corresponding `ready` set. Rebuilds compare source and graph digests, count and exact targets before advancing generation.

When an operation adds or removes a protection-relevant asset reference, it coordinates with storage through the owner transaction and lock contract. The source command and the retirement or purge operation serialize against the same exact target identity. A purge requires proof that all relevant exact owner revisions have current, complete coverage and are eligible under retention and legal-hold policy. A missing, stale or inconsistent set blocks the purge unless the authorized owner performs a complete locked authoritative scan under the declared fallback. A stale graph can still guide investigation. It cannot authorize deletion, grant access or mark a missing link safe.

## 4. Item bank, questions and scoring

An item author edits the candidate prompt, the interaction form, the protected grading rule and the preview as distinct surfaces. They form one reviewed graph and may have different read privileges. The same native representation renders quizzes, assignments and exam forms. Client inputs submit typed values. The server stores accepted evidence before any scoring decision.

| Record | Queryable columns and version pin | Bounded value and constraint |
| --- | --- | --- |
| Item and ItemVersion | Bank, item key, current published version pointer, exact revision, draft compare-and-swap, locale, lifecycle, digest and author | Bounded typed prompt blocks, approved asset revision set, taxonomy and outcomes. Index exact item history and scoped bank selection |
| ItemTranslation | Exact ItemVersion and locale, review principal and approval time | Translated prompt, coverage of exact interaction and option keys, and typed labels and display content keyed to those identifiers. A locale overlay never remaps response semantics |
| ItemStimulusVersion | Institution, stimulus key, exact revision, locale, digest and approval time | Versioned shared stimulus blocks with asset revision set |
| InteractionDefinition | Exact ItemVersion, stable local key, family, schema revision, display order, label, optional exact stimulus version | Discriminated `config` for one interaction family, including supported presentation, accessibility and rich choice values. One row per independently addressed answer field, with unique key and order within the item version |
| MarkingRuleVersion | Institution, stable rule key, exact revision, EvaluatorRelease, minimum and maximum, approved fixture digest, authorizer and time | Protected typed expected values and evaluator parameters. Each accepted scorer validates an exact family-specific payload |
| ItemCriterionBinding | ItemVersion, binding key, exact MarkingRuleVersion or RubricCriterion, maximum and blank/invalid disposition | Bounded lists of local interaction keys and criterion dependencies. Resolve each key within the same item version and reject cycles |
| ItemFeedbackRule and AssessmentHintUse | ItemVersion, rule key and order, allowed trigger and scoped local interaction/criterion keys. Separate attempt item, feedback rule and principal receipt | Protected typed predicate and feedback content. Only the authorized disclosure command returns the permitted selected content |
| RubricVersion and RubricCriterion | Exact rubric revision, criterion key and display order, maximum and point step, publication digest | Approved bounded level values. One criterion row per independent judgment. Level names and descriptors remain a value unless they acquire an independent owner lifecycle |
| AssessmentVersion, AssessmentSectionVersion and AssessmentSlot | Exact version tree, section and slot keys and order, fixed item or item pool version, variant profile, occurrence count, maximum | Definition rows assemble reusable items without copying question source or scoring rules |
| AssessmentDelivery and AttemptItem | Offering, exact content occurrence and approved assessment and policy pins. Realized item revision, slot, occurrence, locale and order | Deterministic private parameters and exact public choice order. Never reroll on resume |
| ResponseRevision and AttemptSubmission | Exact attempt item, stable local interaction key, increasing revision, receipt and accepted time. One terminal submission per attempt | Original typed response, parse/validation evidence, canonical digest, and sealed ordered manifest of accepted revisions |

The compound prompt is a bounded flat preorder list. A leaf carries its own local key and format. A container has a declared kind and optional parent and table or list presentation semantics. An `interaction` node points to the local key of a separately persisted InteractionDefinition. Validate uniqueness, parent existence and order, scope and acyclicity. Preserve the authored interleaving of prose, accessible tables or lists, math and multiple controls. The renderer emits only the validated container semantics. The control record and its accepted value stay independently addressable even when nested inside the prompt presentation.

For a choice field, keep each option's stable `key`, plain fallback `label`, optional fixed position and typed `display_content` inside that interaction's `config`. Options remain ordered bounded values within the exact interaction revision. Use the permitted `leading_content`, `trailing_content`, `accessible_description` and `label_reference_key` for the interaction's presentation. The response references keys, never positions or display labels. The owner persists randomized display order on AttemptItem. A later label edit preserves an option key only if meaning stays equivalent and creates a new item revision. A semantic replacement receives a new key. Expected selections, distractor weights and scoring configuration remain in the protected rule. Candidate APIs never query or serialize those rule fields.

Use ItemTranslation's `labels` value keyed by `interaction_key` and the nested option keys for approved localized controls and rich display. Check that every translated reference targets a declared base control and choice, that IDs remain semantically aligned, and that the declared locale coverage is complete under the published policy. An authorized base-language fallback remains explicit where allowed. The protected ItemFeedbackRule can target the same local control or criterion, with its own trigger, predicate and typed content. Explicit hint disclosure creates an AssessmentHintUse receipt under the exact attempt item. The approved review policy governs when other feedback can appear.

For short text, decimal quantities, symbolic expressions, matching, graph points, ordered answers and files, use the registered interaction schema. A numeric input stores the original lexeme and the authoritative canonical representation when accepted. A math answer may include a parsed bounded syntax tree under the evaluator's validated contract. Its grading rule and evaluator release remain exact separate references. The runtime executes registered algorithms over typed values. Imported PHP, Python, JavaScript expressions and arbitrary XML evaluation instructions remain source evidence until converted to a supported algorithm and verified against approved fixtures.

### Example mapping

An example item asks the learner to select an equivalent value for one half and then type a second valid expression.

| Where | Example |
| --- | --- |
| ItemVersion prompt | Typed text block with the instructions and a typed math display block |
| InteractionDefinition `pick` | `single_choice` with public options `a`, `b` and `c`. The option labels are stored in that version's typed config |
| InteractionDefinition `derive` | `math` with bounded input profile and safe notation help |
| ItemCriterionBinding | One binding of `pick` to an exact selection rule and another of `derive` to an exact mathematical equivalence rule |
| MarkingRuleVersion | Private accepted option key for the first binding and protected typed equivalence target, domain and resource limits for the second |
| AttemptItem | Exact item version and one stable permitted display order, such as `c,a,b` |
| ResponseRevision | The learner's selected key `b` and a separate submitted string `2/4`, each under its exact interaction key |
| AttemptSubmission | Sealed references to those two accepted revisions and their digests |
| EvaluationRun and ItemMarkRevision | Reproducible evaluator outputs under the pinned release and immutable scoring decisions |

A new wording or formula revision leaves the sealed attempt's render, submitted values and grading evidence reproducible. A regrade has its own reviewed compatibility rules and result revisions.

## 5. Source evidence and export boundary

A source backup or external archive enters through TransferArtifact and its protected StorageObject. Preserve its exact hash and source metadata. TransferJob and TransferRecord hold normalized source scope, exact source locator, expected source digest, mapping disposition and proposed target identity. TransferEdge is a separate immutable row for each typed relationship occurrence in one job and plan revision. It preserves its source record, edge key, placement context, target resolution, requirement and order when order matters. Its unique job/revision/source/edge key supports reliable replay. ExternalObjectMap preserves the stable source-to-native relation. These records make conversions reviewable and repeatable. Original XML, HTML or source scripts can be retained under authorized quarantine without serving them as the native curriculum.

A package item whose behavior depends on opaque runtime assets can remain a separately registered PackageVersion and be assigned through an ActivityVersion if the supported security and runtime policy permit. It then has clearly scoped package capabilities and package-owned runtime evidence. It can later be replaced by an approved native activity. The existing raw package is never assumed to provide an editable native quiz, answer key or certified export.

Generated draft content follows the same editor contract. A protected approved PDF is identified by its AssetVersion and verified StorageObject. SourceExtractionRun records that exact source, digest, extraction profile, rights evidence, committed pages and manifest evidence. SourceRegion carries source run, page index, ordinal, normalized page region, classification and a digest and locator to protected extraction evidence. Its unique run/page/ordinal key supports exact page review. Never put raw extracted bytes or private source text into an ordinary course field solely to preserve provenance.

CurriculumAuthoringRun records the exact destination draft and expected revision, the authorized extraction runs and staged plan evidence. SourceDerivationLink binds an approved exact candidate revision and source region to one typed target revision and field path, with the classification and authorized disclosure. The run and derivation link are separate owner records with their own review and retry contract. One source region can support several independently reviewed native outputs. Publication seals the accepted curriculum fields and exact version links. Source review and provenance access remain separately scoped.

An export captures exact CourseVersion, placement and dependency pins under an authorized profile and retains a versioned artifact and compatibility report. It serializes the canonical records into the profile's declared representation. A native exchange archive can carry editable structured content. SCORM can package portable learner launch resources and report outcomes through its supported runtime edition. A profile that cannot represent a native interaction reports the unsupported behavior and requires review before conversion or export. Published content remains in the native stores regardless of how many formats are emitted.

## 6. Read and write verification

1. Read the current EnrollmentRelease and authorize the placement. Select an exact ContentPlacement by course version and stable key, then fetch its versioned dependencies by typed indexed IDs in bounded batches. Avoid one database query for every AST leaf.
2. Fetch locale, rich data, media metadata and labels only after authorization. For native candidate rendering, separately select the public question projection. Verify answer keys and private rule parameters never enter HTML, embedded JSON, exports without answer authority, or browser caches.
3. Save an edit with a stale draft token after a concurrent reorder. The authoritative outline and protected child rows remain as recorded by the accepted edit. The rejected payload can be resubmitted after an explicit rebase.
4. Reuse the same node in two releases that resolve the same stable link to distinct occurrence rows. Each navigation opens the target in the learner's own authorized release.
5. Replace an AssetVersion after a learner submits a file or a teacher publishes a course. The old sealed reference still identifies the exact accepted bytes, with current safety and retention restrictions applied.
6. Export one approved native course twice with identical profile, exact snapshot and canonical input. Check the declared semantic digest, ordered placements, stable identifiers, assets and compatibility report. An archive format with variable packaging metadata must define the normalized digest separately from the artifact byte hash.
7. Reimport a reviewed equivalent native transfer into a deployment whose internal numeric IDs differ. Verify the same durable identity mapping, contents, behavior and held cases. Imported executable or unsupported constructs remain explicit conversion issues.
8. Rebuild one reference set that contains no references. Its exact active generation is `ready` with `entry_count=0` and the canonical empty-collection digest. Removing the set or invalidating its generation must prevent a destructive decision from inferring completeness.
9. Render a compound prompt with an accessible table, localized rich choices and two separate controls. Saving one answer must change only its own ResponseRevision. Requesting a scoped hint must create at most one permitted receipt for that rule and must leave the native maximum and official grade evidence unchanged.
