# 09 Provider synchronization and notifications

## Registration and responsibilities

| Provider profile | System of record | Default data and outage behavior |
| --- | --- | --- |
| Identity | Provider authenticates. LMS owns Principal and educational permissions. | Issuer and opaque subject only for basic binding. Outage denies new unverified login. No email-based fallbacks. |
| Institutional roster | Explicit authority per field and operation, commonly approved identity attributes and roster input from SIS. | Review source IDs, date windows and changes before applying. No absence removal on incomplete feed. Evaluate [OneRoster 1.2](https://www.imsglobal.org/spec/oneroster/v1p2) for supported school exchange. |
| Collaboration | Provider owns rooms and messages. LMS owns desired role and membership derived from offering or class. | Send opaque local mapping, scoped membership and allowed display fields. Loss of chat or calls leaves courses and exams available. |
| Document and media | Provider owns immutable bytes or stream version. LMS owns resource linkage and visibility. | Disallow public sharing of protected LMS data by default. Provider must expose version, access check, removal and evidence to support gated content. |
| External tool | Tool owns tool activity state. LMS owns launch, assessment relationship and official results. | Evaluate [LTI 1.3 and LTI Advantage](https://www.1edtech.org/standards/lti) separately for each supported service. Grade return is scoped evidence and never direct official release. |
| Notification | LMS owns recipient, purpose and preferred channel. Provider owns transport. | Send generic message and authenticated link only. Failure does not reverse grade release, enrollment or exam receipt. |
| Authoring or evaluator | LMS owns authorized request and academic outcome. Provider supplies proposed content or approved evaluation evidence. | Minimize inputs and pin provider tool version. Require human review for authored publication. Timeout keeps grading pending or routes to review. |

Register endpoint as exact approved HTTPS origin. Resolve addresses and check egress target against a bounded allowlist. Block loopback, link-local, private and metadata addresses unless a narrowly deployed approved private connector has fixed routes. Recheck redirects or prohibit them. Validate certificates and prevent untrusted request URLs from controlling provider host or callbacks. See [OWASP SSRF guidance](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html).

Store credentials in secret custody. Change capability, routing or credentials through reviewed connector revisions. Check enabled state, connector revision and approved action at each provider dispatch. Keep current external scopes documented and restrict callback source per connector. If credentials are compromised, suspend connection, invalidate secret, record outstanding effects, and reconcile before enable. Suspension stops future effects while course participation, assessment and academic records remain available.

## Inbound request and snapshot rules

Use a registered transport profile with signed messages or authenticated retrieval. For signed HTTP callbacks, sign method, destination, date, key and content digest with expiry appropriate to the profile, following [RFC 9421](https://www.rfc-editor.org/rfc/rfc9421) where supported. Default accept within five minutes of trusted server time, with agreed provider exceptions. The provider-facing adapter verifies the signed bytes, tenant registration and signature and records protected transport evidence. Its scoped service Principal then invokes the internal `AcceptInboundMessage` command with the transport evidence and payload digest. Verify the evidence binding again before inserting InboxReceipt. The public wire endpoint authenticates the registered provider under its own profile. The internal command still requires the service Principal. A provider message ID must not authorize the action. Replay same signed bytes only as permitted by the replay window and receipt policy.

1. Start a dry run, incremental run, or complete snapshot. Pin connection configuration version and inbound or outbound direction. Allow one applying run per connection and direction by default. Treat provider cursors as opaque tokens. Store them securely and never construct a destination from their value.
2. In each page, validate response size and schemas. Default maximum 500 records and 5 MiB normalized JSON. Resolve external identities against verified maps. Stage unknown, ambiguous or conflicting mappings. Never match by normalized name or email.
3. Compare field authority and local version. A missing field is no-op. A present null clears only when explicitly allowed. A stale current owner version queues conflict. Apply canonical domain command and store received evidence in the same local transaction as a page checkpoint. Use separately idempotent per-record effects for cross-owner operations.
4. A complete snapshot requires provider-declared consistent marker, validated final cursor, and optional trusted total where available. Missing local items become absence-review candidates, even on a complete snapshot. An authorized reviewer approves exact diff against current local versions. A partial or timed-out feed causes zero inferred removals.
5. An explicit signed tombstone can trigger an approved removal command after scope and version checks. Keep tombstone and prior mappings so stale snapshots cannot silently resurrect the resource. Distinguish active provider removal from enrolled student's academic withdrawal or audit retention.
6. Complete the run when all required effects and reviewer decisions are durable. Compare expected cursor on resume and advance only after committed application. Persist SyncPageReceipt in the same commit as local results and the current cursor. An identical received page is safe to replay. A new digest for an already used cursor requires review. Dry run does not mutate domain state or persist a live cursor.
7. On outbound desired-state changes, persist monotonic local desired version, provider object and stable effect identity. A receipt against v7 does not satisfy desired v8. For write timeout, query stable provider resource or use declared idempotency capability. If neither exists, block for reconciliation.

Worked example. Desired class membership is A, B and C at version 21. Page one lists A and times out. Keep A, B and C. The next full run has a confirmed complete marker and lists A and B. Stage C for absence review. By the time a registrar reviews it, C's enrollment is current at a new version. Reject the stale reviewed removal and require a fresh scoped decision.

## Collaboration and documents

Create room desired state per configured offering, section or approved group. Provider-side moderator role derives from an explicit local mapping. Never map every teacher or tenant operator to provider owner. Remove local room launch authority immediately on withdrawal. Provider-side removal is asynchronous and separately tracked. For confidential rooms choose a connector that can enforce removal promptly and suspend shared access under repeated failures. Notifications are generic until reconciliation confirms access.

Link external files by immutable provider version and local AssetVersion or authorized attachment owner. If a provider removes the required version, show a blocked dependency and route to content owner. Do not replace it with an arbitrary latest version. Where course continuity requires a fallback, publish an approved accessible alternative as a new content decision.

## Notification delivery

In-app academic state and receipts are authoritative. For external channels default optional delivery off until purpose-specific preference and verified contact exist. Required institution notices use approved channels under policy and can ignore optional quiet hours only where declared. Default quiet hours are 21:00 through 07:00 in recipient presentation timezone. Use modular local-time interval across midnight. Equal endpoints disable quiet hours. If an endpoint falls within a gap, schedule at first valid local time after it. For a repeated quiet end choose the later instant. Do not send already-expired optional reminders when quiet hours end.

Deduplicate by `source event + person + purpose + channel`. Resolve approved template version and locale before dispatch. Confirm audience, current relationship, verified contact and preference again immediately before send. Record bounce against exact verified contact and suppress further sends until approved re-verification. A lost acknowledgement moves to uncertain. Operator retries only after verified absence or same provider effect key. Use a separate provider webhook permission and receipt for bounce events. Do not expose message payloads or contacts in shared operator logs.

## Management screens

The connector screen lists version, health, granted actions, owner, allowed purpose and last successful synchronization. Hide credential values and rotate through approved action. The reconciliation screen compares external and local values, identifies field authority and confidence, shows stale preview conflicts, and separates explicit from absence-based removals. The notifications screen shows verified channels, quiet time and language. Operators see delivery or suppression reason without seeing private contact values or academic payloads.
